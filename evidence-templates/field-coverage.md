# Field coverage: what the records carry, and what they do not

Staged at pack build from the offline field-coverage audit (a static, checked-in copy of the audit's findings over the raw
ledger, stitched store and raw captures; no live call). **The raw evidence is never edited.**

Each gap names the field, the audit's evidence, what the built pack shows instead (only a tag or join that PR-51b really
implements is named; otherwise `none in the pack; the gap is stated`), the audit's proposed fix (proposed, NOT done), and
why it cannot be fixed before the deadline. The views tag what they show as `recorded (<field>)`, `witnessed-by:<...>`,
`joined-from:<artefact>` or `not recorded`.

Classes (by where the field is written):

- **NEEDS-AGENT-REBUILD**: written by our agent code inside the frozen, approved agent images; the recorded runs' raw records are never edited, so only a rebuild, re-approval and new run can add it. The agent images are frozen and approved.
- **NEEDS-RE-RECORD**: written by our orchestrator / collector / export when the run was recorded; the recorded runs' raw records and captures are never edited, so a recorder or collector change needs a new run or a re-collection; or (register rows) the register is frozen and dated by S3 (T1) and approved in ServiceNow; changing it would need a new version and a new approval.
- **PLATFORM**: the platform does not write it and we cannot change the platform.
- **VIEW**: how the pack and console compute or label the value; no raw evidence involved; the row says whether PR-51b changed it.

The audit's own label (FIXABLE-NOW, JOINABLE, ...) is kept in brackets: it means a recorder could change for future runs or
a value could be joined in a view; it never means a recorded run was changed.
