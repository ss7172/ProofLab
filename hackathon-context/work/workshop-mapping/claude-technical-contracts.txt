3. M02 — INTERFACES AND ROUTING

PROPOSED interfaces, not asserted AWS/ServiceNow endpoint names:
evaluate(request) -> DecisionEnvelope
emit(observation) -> Receipt
callback(result) -> Receipt
pull(scope, cursor) -> SourcePage
query(scope, snapshot, profile) -> Case

They need not be five HTTP endpoints. evaluate is unavailable for strict C16 admission at the fixed gateway unless a supported all-call hook is proven. emit may be an allowed in-process adapter or explicit source capture. pull is our connector. callback is needed only for a real deferred/result workflow. query belongs to M13. The slide’s five architectural problems are not five functions every point must invoke.

Common trusted context: schema_version, authenticated team_id, source/point identity, authorized scope, request/capture identity, event and ingestion times where relevant. Bind team/source policy server-side; caller text and model output cannot choose privileges or omit required controls.

evaluate request adds run_id, action_id, attempt_id, event_type, pinned_bundle_id, exact downstream request identity, model alias/config version and any supported trusted bounds. Response carries decision_id, overall ALLOW/DENY/ERROR, per_control results with control/spec IDs and reason, optional reservation reference. Required blocking ERROR prevents dispatch only where the integration actually enforces it. Monitoring ALERT is not automatically DENY.

emit receipt explicitly distinguishes DURABLE_ACCEPTED from BEST_EFFORT or REJECTED. Durable acceptance requires recoverable raw persistence. Preserve malformed input as a quarantined capture when allowed; report parsing gap instead of silently dropping it. Idempotent repeats match both identity and content; changed content under an old immutable key is a conflict.

callback validates source, original correlation, exact action/policy, permitted transition and expiry. A later approval cannot undo an already executed action. Human silence never becomes synthetic approval. No callback capability is claimed just because its schema exists.

pull response: source_instance, authorized scope/filter, captures, next_cursor, fetched-through position, source-observed-at, pagination/truncation/error state and explicit completeness evidence if supplied. “No next page” proves only that this fetch exhausted its query. It does not prove all expected work was recorded upstream.

Frozen applicability rows:
- Actual model usage/outcome -> C16 actual accounting; C7 only for declared event slots.
- Handoff/tool lifecycle -> C7 declared observations/expected pairs.
- Closed comparable AgentCore metric hour -> C9 pure evaluation and crossing intent.
- Actual ServiceNow delivery/result -> C9 alert-operation evidence; C7 only if explicitly in its declared scope.
- Unmatched in-scope action -> mapping gap, not automatic exclusion.
Control code remains independent of adapter field translation. A second real point can use a different adapter; do not say “nothing rewritten” if entire evaluator logic was forked.

4. M03 — IDENTITIES, VERSIONS AND LIFECYCLE

Canonical IDs and relationships:
- team_id: authenticated ownership scope, never supplied by an untrusted note alone.
- source_instance: namespace including account/region/endpoint/instance/session as necessary for uniqueness. Avoid putting sensitive account identifiers into shareable planning artifacts; real execution records may use authorized opaque aliases.
- run_id: one business fault-resolution run. cid/run header and traceparent are correlation inputs whose actual semantics must be verified.
- action_id: logical intended work in a run.
- attempt_id: one proposed execution attempt/admission identity. An attempt can produce ZERO, ONE or SEVERAL actual executions due to failure/hidden retries.
- provider_execution_id: authoritative actual inference execution, unique within source namespace. Uniqueness key excludes run_id; conflicting claims by two runs must be resolved rather than charged twice.
- observation_id/capture_id: one source assertion/version; several observations may describe the same execution.
- trace_id/span_id: telemetry correlation, not substitutes for business run/execution identity.
- asset_id / registryRecordId / runtime_id: long-lived asset identity, not a call ID.
- control_id plus spec_id/version: obligation and immutable rule applied.
- window_id: metric/runtime/hour scope with explicit expected membership, baseline and versioned source inputs.
- assessment_id/revision versus decision_id: post-fact verdict versus optional live admission.
- accepted_input_revision: normalized/validated fact version, distinct from raw source snapshot.

Transport retry retains idempotency identity; new actual inference gets a distinct execution and normally a new attempt. Hidden SDK retries must not disappear when attempt IDs are reused. Store missing/unmatched identity records; never guess joins from similar text.

Lifecycle: OPEN allows declared new actions; ACTIONS_CLOSED stops new authorization claims; EVIDENCE_FINAL means declared reconciliation is complete or final gaps recorded. Closing actions does not mean all in-flight model requests have finished, and cannot promise no physically delayed send after a prior dispatch claim. Late evidence/corrections create new revisions, not deletion. New policy or new arbitrary run alias cannot reset an existing budget.

6. M05/M06 — RAW CAPTURE, RECONCILIATION AND MANY-TO-MANY EVIDENCE

Independent expected populations:
- C7 needs an authority for intended event slots/adjacent pairs BEFORE filtering to received telemetry. Prefer accepted scenario/workflow obligations or verified agent lifecycle instrumentation. Do not generate expectation solely from logs that survived.
- C16 needs all actual model executions in the declared run, including retries and all three zones. The authoritative gateway inventory may be the source only if its complete scope/finality is proven. Sampling or a few trace spans is not a complete execution population.
- C9 needs expected runtime/hour/metric windows from declared deployment/time scope, not just hours CloudWatch happened to return.
These authorities may differ. A collector is not automatically ground truth for intended work or billable executions.

Capture algorithm:
1 Authenticate source read and fix scope/filter/version.
2 Read page/record and preserve raw bytes/content plus source/capture identity recoverably.
3 Only then acknowledge durable receipt or advance restart checkpoint.
4 Parse typed fields; preserve malformed/unmatched/conflicting records with gap status.
5 Resolve identical duplicates and authoritative revision precedence under frozen rules.
6 Publish accepted normalized revision and exact input lineage; index completeness only covers ingested records.

Changed unversioned source content gets a new local capture identity, not a fabricated source-issued revision. Out-of-order records and late corrections remain visible. Event-time-only watermarks can lose updates; use documented cursor/update semantics or disclosed rescan guarantees. Token-gated source tokens belong in authorized credential handling, not raw export text.

Core repositories:
RawCapture; Run/Action/Attempt; Obligation; Observation; ExecutionUsage; Window; PolicyBundle; EvidenceBinding; Proposal; Validation; Assessment; FindingIntent/Delivery; Investigation; CaseManifest; Gap.

EvidenceBinding fields: binding_id/revision, team, exact fact_id/fact_revision, control_id, spec_id/version, assessed_scope_kind/id, role (measurement/expected population/context/operation), accepted_input_revision and validation/source references.
One usage observation can support both C7 recording and C16 spend. One C9 window can contain several runs. One ServiceNow case can group multiple findings only if every required control/scope/recipient/status remains explicit.

Never aggregate token usage after a many-to-many binding join. First select one accepted authoritative usage revision per execution; sum that set once. Then attach the calculation to its control bindings. A source total corrected from 1,200 to 1,300 replaces its accepted total; it is not an additional 1,300-token call.

Structured exact indexes and narrative relevance indexes are separate. Semantic top-k cannot choose a control denominator. Exact reads include obligations, unmatched facts, unbound inputs and missing references. A model proposal remains a proposal until M12 validates it. A source quote proves the source said something; it does not prove the operational claim is true.

Publish cases only after referenced required versions are durable/resolvable or gaps are explicit. Critical missing inputs prevent completion of a claimed control even if the query itself completes with INDETERMINATE. Export locally resolvable raw/typed inputs for replay. Supplied ledger integrity metadata may be retained/checked through documented facilities; do not add a new signing/hash/Merkle project. Integrity does not establish completeness or truth.

7. M07 — C7 AIA-LOG-001 EXACT EVALUATION CONTRACT

Inputs: pinned C7 specification, independent expected event slots E, expected adjacent-pair set P, matched observations, source completeness and clock eligibility.

Coverage = matched required slots / total required eligible slots. Declare accepted cancellation/eligibility rules in advance; do not cancel obligations because evidence is absent. Alternative valid terminal outcomes occupy the same slot rather than inflating expected count. For E=0, return NOT_ASSESSED/invalid scope under declared policy, not 100% by convention.

Timing: for each expected pair, use trusted ordered endpoints only if clock domain/epoch/precision permit subtraction. A missing middle event leaves its two expected pairs unmeasurable; never bridge the first and third into a new favorable pair. Negative time/clock reset/cross-host offset uncertainty is not a fast pass.

Single-gap comparison uses the exact declared operator. Example from masterclass: gap <5 ms, so 5 ms violates. Exception fraction = violating eligible measured gaps / policy-defined expected eligible pair population, with unmeasurable count and timing coverage reported separately. Do not let a missing endpoint shrink the required population or let a low violation count prove timing pass without required coverage. If the guide/approved spec uses a different denominator, encode it explicitly and preserve missingness; never silently switch.

Illustrative source case: 11/11 events, ten eligible gaps [2,3,4,2,8,3,2,4,3,2] ms -> one timing violation /10 =10%; allowed <=10%, so SATISFIED if all other required coverage conditions hold. The 8 ms exception remains visible. This is illustration, not a measured lab result or recommended threshold.

Verdict: prove BREACHED where an authoritative omission/timing condition violates the frozen rule; preserve that known breach even if other sources have gaps. Missing acquisition alone cannot prove an event never happened. Unknown required coverage without independently established violation -> INDETERMINATE. Distinguish requirement satisfaction from recording mechanism health.

Current-build gate: discarded OTEL spans cannot support a claimed complete source. Verify audit-store/gateway/custom-agent observation coverage and clock resolution before freezing a millisecond rule.

9. M09 — C16 ACN-COST-001 WHOLE-RUN ACCOUNTING CONTRACT

DOCUMENTED authority: gateway input/output token and cost records. Verify actual record shape and complete execution population before final satisfaction claims.

Inputs: pinned run scope/cap/allowance policy; authoritative execution inventory; accepted usage per execution; correlation resolution; accounting units; source finality/completeness.

Algorithm:
1 Enumerate all authoritative actual executions for the run across every declared agent and retry. Distinguish requests denied before inference from actual provider execution. Unknown send outcomes remain unresolved, not zero.
2 Resolve source namespaces and one accepted authoritative usage revision for each execution. Gateway and provider/agent observations of the same call corroborate one charge.
3 Validate nonnegative input/output token fields and documented non-overlap. Cache/reasoning fields are added only if not already included under the source accounting definition. Do not sum parent aggregate and leaf usage.
4 Sum integer input+output across the accepted actual execution set. Monetary cost is separate unless an additional spec declares it.
5 Compare actual run total to frozen cap with exact operator. If max=10,000 and rule is <=cap, exactly10,000 passes;10,001 breaches. Illustrative10,800 exceeds by800.
6 For a population of runs, compare over-cap run fraction with its separately declared allowance. Expected run population is independent, not only returned rows.

Evidence logic:
- Trusted deduplicated unambiguously in-scope subtotal >cap proves breach even with additional unrelated gaps.
- Under-cap subtotal with unresolved/missing executions or usage cannot prove pass.
- Conflicting run attribution or untrusted usage is not silently usable as a confirmed in-scope subtotal.
- Actual usage is not reservation, model token estimate, account hourly ceiling or wall-clock timeout.
- Authoritative cumulative correction supersedes previous accepted usage and triggers reassessment; never add both totals.

Subject and assurance runs are separately identified and linked. Show subject subtotal, assurance subtotal and combined platform spend. The actual declared C16 policy determines inclusion; do not exclude investigator calls merely to improve results. The shared account ceiling includes helper calls regardless. An immutable case cannot include its own later/in-flight composition usage as already final; reconcile those charges into a later deterministic assessment without recursively invoking Nemotron to explain itself.

12. M12 — VALIDATION AND CLAIM COMPOSITION

Validation layers:
1 Schema/types/size limits.
2 Source exists and caller authorized for it.
3 Exact quoted span occurs in the cited source version, with preserved raw coordinates or explicit normalization map.
4 Quote actually supports the statement, including negation; occurrence alone is not entailment.
5 Relationship identifiers/canonical scopes match authorized evidence, not mere text similarity.
6 Field-specific authority/corroboration establishes operational fact if required.

SOURCE_SAYS, verified exact quotation, verified relationship and verified operational fact are distinct types. CANDIDATE is unresolved; REJECTED means the proposal failed a check, not that the world-claim is proven false. Manual adjudication requires named authorized reviewer/reason and original source retention; it does not invent evidence.

Promote via conditional accepted_input_revision. If base changed, revalidate/recompute; do not overwrite newer facts. Corrected source/parse/link invalidates all dependent assessments/claims/caches.
