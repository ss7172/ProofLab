Old worked accuracy examples may remain explicitly illustrative; they cannot be represented as the now-confirmed implementation.
Required tests: complete comparable pass/breach windows, exact boundary, missing hour/runtime, delayed metrics, wrong statistic/dimension, partial hour, zero traffic where applicable, duplicate/revised datapoints and alert on each measured crossing. C02 — ServiceNow AICT / human loop: unresolved source conflict.
Transcript explicitly requires AICT and human loop. Guide /servicenow-integration says the AICT stack can be absent by default, the connector is facilitator-owned, participant steps need no ServiceNow instance, and escalate-to-incident.py is stretch.
Resolution: record REQUIREMENT_CONFLICT and ask the organizer one precise question: "For scoring, is participant-specific AICT connection plus a named-recipient human-loop demonstration required, or does the guide's facilitator-owned/default-absent path satisfy the masterclass/transcript requirement? Do not silently let new guide prose erase the transcript correction, and do not invent a participant ServiceNow build requirement the guide cannot support. While awaiting resolution, finish all independent control/evidence tasks and retain the existing intended M14 route as CONDITIONAL / FACILITATOR_DEPENDENT. Include the conflict and its impact in the gap list. A deployment that lacks access cannot be labelled integration verified.
Human reply remains explicitly out of scope in the masterclass. Whatever integration is accepted, evidence must distinguish intent, dispatch, remote presence/assignment, actual notification, observed response and bounded silence. A successful escalation script alone does not establish recipient, readback or a human answer. Record platform delivery in the permitted scope, not a supposed private instance.

C03 — C16 inline prevention: platform contract constrains the bonus.
Guide /platform-contract says gateway/PDP accept no custom code; Cedar ConfigMap is configurable, but there are no token attributes or token meter. Guide confirms per-run post-hoc accounting as floor and inline enforcement as bonus.
Resolution: baseline C16 is complete post-run accounting/reconciliation. Existing Cedar policy can establish only what its actual input attributes and evaluation semantics support; it cannot enforce a live token budget merely because it can ALLOW/DENY other requests. Do not put our M10 state machine into the fixed PDP or claim a ConfigMap supplies atomic reservations.
Conditional bonus: only if a separately permitted, unavoidable inference boundary and trusted accounting bounds/state are demonstrated. No such alternative is established by the summary. A wrapper around our own investigator or one agent covers that scope only; it is not whole-run prevention across all three agents and retries.
Effect: M02 adapters map to actual permitted interception/log paths; M07/M09 post-hoc tests remain core. M10 is not on the baseline critical path. Mark its deployment unresolved/conditional until an approved all-call point, dispatch guarantee, upper bound and atomic store are proven. If unavailable, cut prevention honestly without blocking completed post-hoc C16.

C04 — Submission location: S3 is the scoring source, not the laptop.
Guide provides submit.sh to a team S3 evidence bucket; it prints a short-lived presigned URL. Judging reads the bucket.
Resolution: M15 owns a submission task that runs the inspected permitted script only after the full final package is validated, then verifies the expected team bucket/prefix and uploaded manifest/artifacts. A local portable copy remains useful for rehearsal/rechecking but is not submission proof. M13 must expose the tool/records in the organizer's expected manner; the guide's exact expected package/entrypoint still needs extraction.
Keep bucket scope, object keys/version identifiers and upload/readback outcome as non-secret provenance. Treat a presigned URL as temporary bearer access: do not reproduce it in public/shareable architecture or long-lived task exports. Do not expose AWS credentials. URL expiry and environment lifetime are distinct; verify what judges will use and the actual submission deadline.
Do not assume submit.sh covers all six categories simply because it uploads one file. Inspect its contents, inputs, naming, allowed file types, overwrite behavior, exit status and readback instructions. Preserve failed/partial-upload status; local script invocation alone is not successful delivery.
Effect: revise any "judge reads laptop" language in M13/M15. Offline rechecker remains a reproducibility feature, not a substitute for S3 submission.
