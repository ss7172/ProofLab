ASSESSMENT
The design handles difficult accounting and evidence distinctions unusually explicitly: unknown dispatch retains liability, duplicate observations do not become duplicate charges, decisions are separate from assessments, immutable specifications stay outside the live register path, and missing evidence cannot create a pass. The remaining shortfall is conversion of these principles into filled control contracts and executable acceptance matrices. Repeating “freeze/declare/verify” does not yet resolve the choice.

1. HIGH — Control7 still lacks a concrete event universe and timing algorithm.
The latest contract correctly requires independent obligations, but neither document supplies the initial event taxonomy, per-action required phases, denominator formula, or precise eligible gap pairs. Thus two competent implementers could return different results. Add a machine-readable obligations table for run lifecycle, model attempts, tool actions and boundary crossings; identify which source independently creates each obligation. Specify expected-only denominator behavior, conflicts/extra events, cancellation/denial obligations, missing timestamps and zero-pair results. Define timing on ordered causal streams with an identified clock basis. Acceptance cases must include an entire missing attempt, missing cross-zone receive, duplicate delivery, out-of-order events and zero eligible gaps. If an independent population cannot be observed, the affected scope remains indeterminate.

2. HIGH — Control9 is a candidate measurement, not yet a reproducible experiment.
“Correct fault_id / eligible labelled scenarios” leaves exact matching, multi-fault cases, abstentions, missing output, timeouts, label access, minimum sample size and window allocation unresolved. Add a frozen scoring function, baseline dataset manifest disjoint from assessed cases, label authority, comparison cohorts, minimum count and scheduled-window manifest. Define direction and relative-drop formula, allowable violating-window proportion, monitoring coverage, and delivery evidence. A missing expected measurement can breach coverage while performance remains unknown. A run query must list its relevant windows without claiming window drift measures that run’s accuracy. Obtain organizer acceptance for any simulated corpus before treating it as completion; otherwise explicitly concede the unavailable branch.

3. HIGH — Turn per-observation violations into branch/claim assessments deterministically.
Current prose risks different interpretations of a violating gap/window/run when nonzero exception allowances are permitted. Add a truth table: observation limit violation → complete eligible population and exceptions → branch requirement verdict → claim rollup. Unknown denominators forbid a tolerant aggregate pass; a known sufficient lower bound can establish a breach. Preserve separate operation and delivery states. Implement identical reference cases for primary and independent checkers, including allowed exceptions, unknown population, late correction and mixed policy versions. Control16’s robust protocol deserves a concrete configuration and recovery matrix; its illustrative 10,000 cap still requires a pre-assessment rationale.

4. HIGH — Complete-control acceptance must connect evidence, integrations and all six artifacts.
Create one row per control with actual source fields, independent population, joins, pinned spec, passing case, genuine/accepted breaching case, query command and exported records. Map every required artifact to a filename and acceptance check. Add a remote AICT readback proof and model-use verification to the deployment gate, without assuming inventory integration proves trace/finding delivery. A denied overspend proves prevention, not the required actual breached case; cloned-export damage proves checker sensitivity, not missing live telemetry.

5. MEDIUM — Delivery order is credible but not allocated.
Assign two owners, bounded work blocks and explicit stop/go checkpoints. Resolve all-zone usage, expected-event visibility and authoritative drift labels in the first access block; escalate unavailable source requirements immediately. Complete one exportable control before parallelizing the remaining two. Make inline enforcement, second-point demonstration and adaptive proposer conditional on artifact readiness. The present dates, broad gates and optional-feature cuts help, but do not establish two-person capacity.

SOURCE FIDELITY
The proposal correctly preserves post-run evaluation as the floor, mandatory dated specifications and six artifacts, two-minute query, unchanged rules across pass/breach cases, and the exclusions for cryptographic sealing and actual human replies. AWS/ServiceNow hooks, tenant permissions, source completeness and accepted datasets remain unverified; documentation alone cannot settle them.
