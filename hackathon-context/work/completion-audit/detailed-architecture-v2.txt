PROOFLAB — DETAILED ARCHITECTURE AND COMPLETION PLAN
Design revision for the October4–6 hackathon; all implementations and live integrations remain proposed. This document supersedes earlier architecture choices where they differ; the invocation contract remains supporting detail. No numeric design score means percent built or probability of winning.

0. PURPOSE AND OFFICIAL ORDER
C-FM-01: during fault resolution, the three collaborating agents meet declared event-recording, drift and token-spend requirements. Target all3 controls completed end to end:7 AIA-LOG-001,9 AIA-ARC-006,16 ACN-COST-001. Minimum1; complete2 precedes1, complete3 is the full set. Quality decides among comparable coverage; extras then differentiate. The new attached slide is the judging rubric, printed27 (physical25 in the full deck). Actual demonstrated state remains0/3. Existing HTML explanations are design documents, not live applications.

Completion of a control means its declared scope, dated justified rule, actual mechanism, independent population/measurements, passing and genuine or organizer-accepted breaching cases, reproducible test and export all exist. A fully working detector can report a breached requirement: 'control complete' is not the same as 'all runs green'. A named gap does not complete an unmeasurable branch.

1. DEPLOYABLE SHAPE: ONE PYTHON DISTRIBUTION, SMALL NUMBER OF ENTRY POINTS
A. Platform adapters: shared-model gateway adapter, zone-boundary adapter, telemetry source connector and ServiceNow connector. Install/configure only through supported workshop hooks. First second-point target is gatewayB handoff; use a permitted tool boundary ifB cannot be modified, or a read-only source with an honest observation label. Different adapter code is expected; control/evidence logic remains unchanged.
B. Assurance backend: one shared package, entry points for synchronous admission and asynchronous collection/window assessment/export. Run inside permitted AWS compute when live enforcement requires reachability. Prefer an allowed gateway function/wrapper for admission and an allowed scheduled/event worker for assessment. Do not assume permissions for Lambda, a long-running container, scheduler or a public API. Compute choice is closed by the first capability gate. If unavailable, retain the same pure tests in an offline read-only package and downgrade live claims.
C. ServiceNow team configuration/integration: team-prefixed asset connection plus real permitted alert/finding/owner workflow. It is an external governance integration, not a second copy of the control engine or an assumed kill switch.
D. Judge client: local CLI with optional small HTML UI reading the same query results. Authenticated cloud evidence download or portable local bundle; no laptop dependency in the inference path. No public tunnel or third-party hosting assumed.

Preferred storage if enabled: single-region DynamoDB for atomic budget/run/attempt/minimal-outbox state; S3 for immutable policy versions, raw observations and exported bundles; local SQLite index generated from bundle JSONL for fast offline queries. These are proposed mappings, not verified workshop entitlements. A conditional-write/transaction-capable permitted store can replace DynamoDB through the state repository contract. S3/SQLite never substitutes for cross-worker atomic admission state. Existing OTEL transport/source is reused; add no new bus merely for diagram symmetry.

Proposed package modules, not created files:
contracts/ schemas and enums; policy/ validation and applicability; adapters/ platform translations; runtime/ admission, dispatch, settlement; sources/ obligation and usage reconciliation; controls/ c7,c9,c16 pure tests; governance/ ServiceNow delivery; query/ query, export and reference recheck; scenarios/ fixed authorized campaigns.
No graph database, extra orchestration platform, cryptographic ledger or multiple assurance agents. Retain/verify supplied Nemotron usage; custom agents follow required workshop model/hosting rules. Optional bounded Nemotron test selection is the last increment, not an exemption from model requirements.

2. NORMALIZED CONTRACT AND CONTROL ROUTING
Shared entry points: evaluate(request)->overall decision+per-control results; emit(observation)->explicit durable/best-effort receipt; callback(later result)->correlated receipt; pull(scope,cursor)->source page+completion; query(control,scope,as_of)->recomputed assessment. query is for judges, separate from four enforcement transports. SDK/sidecar is an adapter form. These are our proposed names, not existing vendor APIs.
Admission request: schema_version, authenticated team/point context, run_id, action_id, attempt_id, event_type, pinned_bundle_id, exact request identity, model/version/accounting options, trusted facts/bounds. Response: decision_id, overall ALLOW/DENY/ERROR, per-control control_id+spec_id+decision+reason, attempt_id, optional reservation_id and amount. Monitoring ALERT is not an admission refusal unless explicitly declared as a blocking policy.
Mapping is frozen in the authorized policy bundle; caller cannot omit a required control or select an easier version. DENY or required-admission-control ERROR prevents dispatch. Recording/monitoring controls do not become blocking merely because they share an action. Proved-undispatched reservations can be cancelled after another gate denies; ambiguous ones remain reserved.
Routing rows:
model.requested at shared gateway ->16 admission;7 request/decision facts.
model usage/outcome ->16 settlement and assessment facts;7 outcome recording.
zoneA/zoneB handoff send/receive ->7 observations and pair reconciliation.
permitted tool/handoff lifecycle ->7 according to declared scope.
comparable metric window ->9 off-path evaluation and alert.
ServiceNow delivery/result ->9 alert-operation evidence and optional declared7 recording.
Unmatched in-scope actions become mapping gaps, not silent exclusions. A multi-run window has explicit run membership rather than a fictitious single run.

3. CANONICAL DATA AND KEYS
All records include schema version, team, provenance class and stable source references where applicable. Provenance: LIVE_SUBJECT, AUTHORIZED_TEST, REPLAY, COUNTERFACTUAL_EXPORT, SYNTHETIC. Exact schemas should be encoded during implementation from these required fields; no cloud table names are asserted.
PolicyBundle key(team,bundle_version): immutable spec contents, applicability version, effective interval, evaluator versions, control owners, freeze time, baseline/dataset references, declared source/completion rules. Reject missing/unsupported/expired bundles. Publishing a new bundle does not alter historical assessments or split an existing run's budget. Declare pin-to-completion vs stop-on-revocation; urgent revocation uses a separate distributed stop signal, not per-call registry reads.
Run key(team,run_id): owning scope, bundle_version, opened_at, status OPEN/ACTIONS_CLOSED/EVIDENCE_FINAL, version/CAS, settled_tokens,reserved_tokens, declared expected source set, late-data deadline and capability snapshot. Admission/closure share conditional concurrency checks.
Attempt key(team,run_id,attempt_id): action_id,parent_attempt_id if true retry, point, model/version, immutable request identity, provider_execution_id when known, state, reservation, actual usage, dispatch ownership and transition sequence. New actual inference retry =new attempt; duplicate transport retry=same attempt.
Obligation key(team,run,action_or_attempt,event_kind,phase): created_by independent expected-work authority, expected_source, causal parent, eligibility, deadline, cancelled_reason if proved never dispatchable. Dynamic work adds obligations before execution wherever verified hooks allow.
Observation key(team,source,source_record_id): event_id, run/action/attempt links, type, actor, event_time, ingestion_time, source sequence/clock domain, payload/source ref. Multiple observations can corroborate one execution. Conflicting IDs or totals retained, never silently merged.
UsageEntry key(team,run,authoritative_execution): admitted attempt link, input/output and defined cache/reasoning accounting, authoritative source, corroborating observations, revision. Never sum aggregate parent and leaf usage. A reused attempt ID for two actual provider executions is a conflict to resolve, not permission to drop one charge.
EvidenceBinding key(binding_id): observation or usage/window ref +control_id+spec_id+run/window+role. One observation may support7 and16; it is charged once.
Window key(team,cohort,window_id): baseline_id, scenario membership, expected count, metric/scoring version, time interval, closure/source checkpoints, valid result refs and missing set.
Assessment key(team,control,scope,revision): exact input refs/versions, event-time interval, as_of ingestion cutoff, expected/observed denominators, measures, exceptions, requirement verdict, operation state, evidence sufficiency, provisional/final status, gap refs and supersedes.
Alert/Finding key(team,control,assessment,kind): local idempotency identity, named owner/recipient, delivery attempts, actual remote record ID, PENDING/DELIVERED/FAILED delivery, separate response state, remediation/retest references. No fabricated human acknowledgment.

4. CONTROL7: EXECUTABLE EXPECTED-EVENT CONTRACT
Initial in-scope taxonomy covers the three-zone subject run. Freeze the actual implemented source mapping; these are required logical obligations, not a claim that vendor payloads use these names.
Run admission: lifecycle authority commits run.opened; closing actions requires run.actions_closed and source completion records.
Model action: dispatcher/coordination journal registers model.requested; expects admission.allowed, admission.denied or admission.error. A recoverable admission error is its own declared terminal decision; an unrecorded outage remains a recording gap, never an invented denial. If allowed and actually dispatched, expects dispatch marker and one authoritative terminal outcome: completed, failed, or explicitly unresolved. Successful known usage requires a usage assertion; failed/disconnected outcomes may still incur tokens and require reconciliation. Denied never-dispatched work needs denial evidence, not fabricated provider usage.
Each gatewayA/B handoff: sending lifecycle creates handoff.sent and expected matching handoff.received, joined by stable handoff_id; refusal/timeout is its own declared terminal case, never silently deletes expected work.
Tool action: orchestrator registers tool.requested before dispatch; expects one tool.completed/tool.failed or unresolved outcome, with result/source reference. Include only explicitly declared tools across verified sources; excluded relevant sources remain a scope limitation.
Each real retry adds a new attempt and its obligations, while the previous attempt remains reconcilable.

Dynamic example: three initial model attempts M1,M2,M3; M2's genuine retry M2R is separately registered before execution. All4 belong in expected accounting. Losing every telemetry record ofM2R still leaves an independent obligation/provider inventory entry. If the platform cannot supply an independent work inventory or verified complete interception, completeness cannot be asserted. The adapter's surviving logs alone are not an expected population.

Coverage: E=unique required obligations due by declared cutoff; O=valid matching recorded obligations; coverage=|E intersect O|/|E|. Extra, duplicate, orphan and conflicting events reported separately; cannot inflate numerator. Missing events do not disappear fromE after timeout. Unknown source coverage means denominator is unproven: no full-scope SATISFIED. A proved violation may still establish BREACHED even when other evidence is missing.
Timing: define consecutive events only within each declared ordered producer stream for one run, ordered by producer sequence and measured by a valid monotonic clock/epoch. Parallel branches are separate streams; no subtraction of unrelated host clocks. Restart/clock discontinuity creates an unmeasurable gap, not a new apparently clean stream. Exact policy declares gap< G, so violation isgap>=G. Let eligible expected adjacent pairs beP, measurable pairsM, violating pairsK, unmeasurableU=P-M. Report all4. With complete pairs, violation share=K/P; compare with allowedB7. With missing pairs, lower boundK/P and upper(K+U)/P bound the share; claim pass only under the predeclared completeness/measurement rules. P=0 returns timing NOT_ASSESSED, not automatic success.

Policy parameters not yet justified: coverage targetC, gap limitG, allowedB7, minimum evidence/timing coverage, eligible streams and late deadline. Complete the rule from permitted pre-assessment baseline/purpose, name owner, date it, then freeze. Illustrative fixture: E11,O11; ten gaps with one>=5ms; allowed10% ->satisfied if all other declared conditions hold. A second violating gap ->breached. These values mirror teaching examples, not final thresholds.
Done gate: accepted scope spans all required zones; independently justifiedE; coverage+timing test; pass/breach cases under same spec; missing-whole-attempt and out-of-order cases; source-backed query and export.

5. CONTROL9: DIAGNOSTIC PERFORMANCE EXPERIMENT
Chosen metric proposal: single-fault diagnosis exact-match rate, higher is better. Canonical agent result contains scenario_id,run_id,predicted_fault_id,completion_status,completed_at. Ground-truth scenario manifest contains scenario_id, approved fault_id, cohort, eligibility, split, scenario parameters and expected window. Labels come from accepted workshop scenario authority or organizer-approved reference corpus; never infer truth from agent agreement. Freeze any alias normalization table.
Scoring: eligible single-fault case scores1 only for one valid canonical predicted_fault_id exactly matching label before declared timeout. Wrong ID, multiple IDs, abstention, malformed output, confirmed crash or confirmed timeout scores0 when authoritative evidence proves that outcome. Missing telemetry/outcome is UNKNOWN, not0 and not excluded. Unlabelled or multi-fault scenarios are ineligible only under the predeclared manifest rule; record them and limit the claim. Never exclude cases after seeing performance.
Baseline: separate calibration/labelled baseline cases from assessed cases byscenario_id; no assessed results in threshold selection. Both sets use the same declared fault/severity distribution, scoring function and task/cohort. Record model/prompt/tool/dataset versions; stratify results when these differ. A model/prompt change can be an explicitly declared candidate comparison, not an unrecorded mixing of cohorts. BaselineB=mean of known binary baseline scores with required coverage and justified minimumN. Must bepositive. B=0, too few cases or unproven labels ->NOT_ASSESSED; do not substitute confidence.
Windows: freeze a manifest of fixed-size scenario batches and their cohort mix, plus their scheduled/deadline intervals, before assessment. The monitor checks scheduled completion and assesses each completed comparable batch. This is a proposed monitoring definition whose scope/benchmark acceptance must be confirmed, not a claim to monitor all real production performance. Each expected window and its case countN is registered ahead of execution. Missing/unstarted scheduled work remains in expected coverage. Each run query lists associated window(s); a window drift result is labelled window-scoped, not the individual run's accuracy.
For fully measured comparable windoww: Mw=correct/N; dropDw=100*(B-Mw)/B. Negative drop means improvement. Window violates whenDw>D. Over an assessed interval, compare violating-window fraction to allowanceB9; separately require declared measurement-window coverage. Missing windows remain unknown. A known violation proves breach when allowance is0; tolerant aggregates use known violation/expected-window lower bounds and missing-window upper bounds. Never treat absent windows aszero drift.
Alert: on a substantiated drift breach, create idempotent finding linked to assessment/spec/window, route to named owner, persist actual delivery response/readback. A delivered alert does not erase the performance breach. A pending human response is acceptable evidence if honestly recorded; pending/failed delivery is not delivered.
Illustrative mini-fixture only: positive baseline8/10=.8; full window8/10 gives0% drop;7/10 gives12.5% drop and breaches example10% limit with0 violating windows allowed. Window with9 known outcomes of10 remains incomplete; report outcomes and missingness rather than claim9/9. These ten-case counts are arithmetic fixtures, not adequate sample-size justification. Before assessed runs choose and justify actualN, timeout,D,B9 and coverage from purpose/baseline and permitted event budget; unresolved values block scored execution.
First-session gate: accepted labels/scenario execution, deterministic result mapping, baseline/assessed separation, comparable batches and permission for degradation scenario. If labels are unavailable, ask organizers about a specific disclosed reference corpus; otherwise9 remains unassessed. No invented substitute metric to obtain green results.
Done gate: frozen valid baseline + actual comparable windows + pass/breach + missing-window case + actual alert recipient/status + run-to-window query + exported corpus/measurements with correct scope.

6. CONTROL16: WHOLE-RUN ACCOUNTING AND OPTIONAL PREVENTION
Accounting test is the completion foundation. Whole-run actual usage sums authoritative input+output for every actual attempt across all3 agents and retries with declared cache/reasoning semantics. Reservation is exposure, not measured spend. Complete inventory and reconciled usage required for an under-cap pass. Known trustworthy subtotal>N proves run breach even with other missing usage. N remains a justified pre-assessment parameter;10,000 only an illustrative fixture. If allowed over-cap run fractionB16 is nonzero, declare assessed run population and evaluate exceptions separately; individual overshoots remain visible. Preferred simple declared policy, subject to justification, allows0 over-cap runs.

State machine:
NONE ->RESERVED: authorized point; runOPEN; correct effective pinned bundle; matching immutable request; atomic capacity check settled+reserved+bound<=cap; create unique attempt +reserve +minimal decision/outbox.
Existing same admission ->existing record: identical request identity returns same state, never grants a second dispatch. Conflicting payload rejects.
RESERVED ->CANCELLED: only proven undispatched and no previous dispatch claim; atomically release reservation, record reason. DENIED is a recorded no-reservation decision, not a provider execution.
RESERVED ->DISPATCHING: atomically require runOPEN and the valid authorized execution context while conditionally claiming attempt ownership once; execute exact bounded model request. Changing prompt/model/output options invalidates prior admission.
DISPATCHING ->OUTCOME_UNKNOWN: ambiguous remote send or lost response; hold liability. Expired lease cannot justify redispatch. Repeat downstream only if verified provider idempotency guarantees it; otherwise a deliberate fresh inference is a new attempt+reservation while old liability stays.
DISPATCHING/OUTCOME_UNKNOWN ->SETTLED: reconcile authoritative usage/provider execution; atomically transition once, add actual tokens, release reservation, and journal the update. Genuine late outcomes can resolve unknowns.
SETTLED ->versioned correction: preserve both source assertions and revisions; apply one explicit authoritative correction under a declared reconciliation rule, never sum duplicate reports. Actual>bound is retained, exposes prevention failure, and stops admission.
OPEN ->ACTIONS_CLOSED atomically closes both admission and new dispatch. Dispatch transactions check the same run state, so closure races with both admission and RESERVED ->DISPATCHING. Already DISPATCHING requests may still complete; closure does not cancel a sent provider request. A recovery worker cancels remaining RESERVED attempts only through a conditional proven-undispatched transition and releases each reservation once. EVIDENCE_FINAL is an as-of evidence cutoff after required source reconciliation or explicitly recorded gaps/late-policy expiry, not proof every remote action finished. Unknown liabilities remain disclosed and reserved; final can beINDETERMINATE, never silently pass.

Datastore-neutral admission transaction preconditions: team ownership, run version/status, authorized bundle, absent attempt or exact idempotent match, sufficient exposure. Writes: run reserved+bound/version++, attemptRESERVED, minimal transition/outbox. Evaluate capacity is a pure function; coordinator owns retries/CAS. Settlement transaction checks attempt not already settled and source authority, updates run+attempt+transition together. Do not separately ConditionCheck and Update the same DynamoDB item; put conditions on writes if that store is used.
Minimal durable journal belongs to coordination; rich ledger export remains async. Store unavailable =>deny governed admission with explicitERROR, adapter recovery if possible, expose any unrecorded gap. ALLOW must never precede durable reservation. Dispatch identity, source bounds, retry coverage and bypasses must be verified before claiming strict prevention.
Done gate: full3-agent/retry accounting, unchanged dated cap, passing and actual/accepted breaching run, conflicting/duplicate/missing-usage cases, reproducible export. Preventive bonus separately requires verified hook+bound, live deny, concurrent race and crash tests. A denied attempt is not an actual breached run.

7. VERDICT COMPOSITION AND CLAIM COVERAGE
Store three dimensions: requirement satisfaction, safeguard operation, evidence sufficiency. Delivery/response are additional statuses, not substitutes for performance.
Known measured violation beyond declared allowance ->BREACHED even when unrelated gaps remain; disclose sufficient proof scope.
Fully assessable population and all limits/allowances satisfied ->SATISFIED.
Selected control with inadequate/conflicting evidence and no proved breach ->INDETERMINATE.
No implemented/eligible assessment (e.g.invalid baseline) ->NOT_ASSESSED.
For incomplete tolerated populations, compute lower/upper bounds on violation share where possible; use them only with declared completeness requirements. Unknown denominator cannot support a tolerant pass. Preserve each individual exception even when aggregate is permitted.
C-FM-01 manifest lists7,9,16 separately with assessed scope and completion evidence. Any substantiated required breach ->claimBREACHED for corresponding declared scope; otherwise any unknown/unassessed branch ->NOT_ESTABLISHED; all required branches satisfied with matching scope ->SATISFIED. No averaging or majority vote. Controls completed count is a separate submission attribute from their verdicts.
Late data creates a new linked assessment revision with exact as-of inputs. Historical specs/results remain reproducible. A finding closes only with a passing new-run/relevant-window retest and actual required owner action; earlier failure remains visible.

8. CAPABILITY GATES: ACTUAL ACCESS DETERMINES THE DEPLOYMENT
Every adapter record lists source, identity, required fields, transport, completion guarantee, blocking ability, authorized team scope, and PROPOSED/FIXTURE_TESTED/LIVE_VERIFIED/UNAVAILABLE status.
Model gateway probe: one actual3-agent run plus real retry; correlate rootrun/action/attempt/provider IDs, usage/model IDs, sequence/completion. Verify exact gateway identity, write hook vs log-only, output-bound enforcement and bypasses. Inline+complete ->admission bonus eligible; log-only+complete ->accounting detection; unproven usage population ->no spend pass. AgentCore Gateway tool interception is not proof it sees all model inference.
Zone/tool probe: one matched sender/receiver handoff and one approved failure; verify independent expected work, actual event source and clock basis. Incomplete source scope ->record limitation; do not silently claim whole-system7.
C9 probe: execute one accepted labelled scenario and map exact result; verify independent label authority, cohort/splits, scheduling and source status. Failure closes the3-control path until resolved, not a reason to invent scores.
ServiceNow probe: team-prefixed connection/asset readback; actual permitted alert/finding route with remote record ID/status and named owner; separately test trace/run link. Required AICT/human-loop integration remains a release gate. If only inventory works, preserve that fact but do not claim full finding/trace integration. Use a documented permitted alternative only; unresolved mandatory scope needs organizer resolution.
Model probe: verify actual supplied/custom model invocations satisfy Nemotron requirements. An optional proposer is not a loophole.
Compute/storage/network probe: select enabled approved host and authenticated path. No laptoplocalhost/public tunnel in runtime. If no transactional store/hook is available, remove preventive bonus, keep honest complete detection if data permits. If no approved cloud worker is available, use allowed exports/CLI for assessment while retaining mandatory platform integration; do not move assessed agents outside providedAWS/ServiceNow.
Each gate has evidence sample, responsible person, resolution decision and remaining gap. A failed source probe should stop speculative adapter coding for that source until organizer clarification or a verified alternative appears.

9. FIXED ACCEPTANCE AND ADVERSARIAL CAMPAIGN
All are planned scenario names, not actual run IDs. The real execution assigns immutable run IDs and records eligibility/provenance/seed. Any unsafe shared-system perturbation requires an approved isolated scenario; otherwise test cloned exports and label that limitation.
C7-PASS: all expected events, valid timing within allowances ->SATISFIED.
C7-COVERAGE-BREACH: authorized source-level record loss with independent expected obligation ->coverageBREACHED. Copied-export removal is separatelyCOUNTERFACTUAL_EXPORT and proves checker sensitivity only.
C7-GAP-BREACH: approved delayed event makes violations exceed fixed allowance ->timingBREACHED; keep coverage separately.
C7-REORDER/DUPLICATE: ingestion order/transport repeat changes neither population nor canonical event-time sequence.

10. SIX-ARTIFACT RELEASE CONTRACT
Proposed command: prooflab bundle --assessment-set <id> --out submission/. These commands are interface specifications, not built executables. It freezes an assessment-set manifest and exports:
1 evidence/ observations.jsonl, obligations.jsonl, usages.jsonl, bindings.jsonl, windows.jsonl, assessments.jsonl, alerts.jsonl plus required raw-source files. Every reference resolves in bundle or is an explicit disclosed unavailable source; no remote-only critical inputs.
2 thresholds/ exact dated policy bundles, rationale, owner, metric, limits, allowances, measurement basis, baseline/dataset manifests and effective versions. An example/template is not a declared final spec.
3 tool/ runnable query entrypoint and independent arithmetic reference checker, README and required environment/locked dependency instructions. Queries work offline on the bundle; the reference checker validates calculation, not institutional independence or source truth.
4 runs.json real pass/breach identifiers, which controls each case assesses, provenance and organizer acceptance where needed. Several cases may be necessary to complete3 controls; the slide's two named runs are the minimum, not permission to skip a branch's demonstration.
5 architecture.svg one-page actual deployment/invocation boundaries and secondpoint status; final version must match deployed behavior, not aspiration.
6 gaps.json +readable gaps.txt with scope, evidence, effect on claim/bonus, owner and unresolved reason.
Supporting manifest.json includes package/schema/evaluator/reference-checker versions, files and exact input identities, scope, policy versions, source completion, event-time intervals/as-of cutoffs, capability state and C-FM-01 branch status. rehearsal.json/adversarial.jsonl carry optional proof; not invented extra official requirements. Cryptographic seals are not prerequisites.
Release validation: required6 artifacts present; input references resolved; thresholds predate assessed runs; unchanged rules across pass/breach; no fabricated live labels; capability/model/AICT evidence included; every claimed control has end-to-end accepted cases; gap and claim statuses consistent. Failure makes release NOT_READY with specific reasons. Do not mark a template as the evidence file.

11. JUDGE EXPERIENCE AND COMPETITIVE DIFFERENTIATION
Query command proposal: prooflab query --bundle submission --control 9 --run <actual-id>, or --window <id>. First screen: claim branch coverage, selected scope, requirement verdict, operation/evidence state, frozen spec/date, formula+counts+exceptions, source links, gaps and actual finding status. C9 run query explicitly resolves applicable window(s). Export recheck is one command; no LLM narration required. The query index contains all relevant records and is rebuilt from exports, not manually authored verdicts.
Acceptance: two fresh-start rehearsals with another person selecting arbitrary controls/scopes from the assessed set, each<=120seconds; record actual times and any failure. More evidence/scenarios does not justify a slower answer. Small explicit assessment set and prebuilt index are the primary latency strategy;5ms runtime claim in the slide is illustrative, not an established gateway SLA.
Default demo3beats: selectedcontrol/run answer; one live permitted decision or honest measured breach; one evidence challenge with original failure and new-run retest. Other controls/source details are drill-downs. Presentation slot length must be confirmed; the2minute query limit is published.
Winning path: completed3-control set; inspectable correct evidence; real failures; offline reproducibility; actual concurrent admission; executed adversarial fixes; real secondpoint reuse. A safe missing-record challenge should cause coverage failure/uncertainty rather than a false green lower token total. Original failures remain visible. Extra AI roles do not automatically add rubric value.

12. TWO-PERSON DELIVERY WITH CUT LINES
RoleA: contracts, source normalization, Control16, runtime state/admission and Control7 event obligations.
RoleB: Control9 labelled baseline/windows, ServiceNow integration, query/export/release and independent rechecker. Both use AI-assisted implementation and cross-review each other's artifacts; this does not claim organizational independence.
First access block (planning timebox up to90minutes, not promised task duration):A verifies3-zone usage/expected work/hook/store;B verifies accepted labels, actual Nemotron and ServiceNow route. Record capability outcomes; choose deployment branch. If critical sources fail, obtain specific organizer guidance or select documented alternatives; stop speculative coding, preserve blocked branch and reassess target.
Day1 target: shared schema/policy validation fixed; one complete16 accounting slice with query and named actual cases; in parallelB proves C9 first labelled result and real ServiceNow readback. Complete a skeleton release export immediately. No admission state machine before usage/accounting gate.
Day2 target: A completes7, B completes9/query/AICT, merge a3-control bundle. A adds inline gate only after shared base meets completion checks;B runs fixed adversarial/recheck/release. If all3 not complete, do not start adaptive work or elaborate UI. Missing-source problems are reported early, not hidden as unfinished code.
Feature freeze T-minus12hours, whereT is confirmed submission cutoff. By freeze: retain the highest completed control count with mandatory integrations/artifacts, explicitly cut unverified bonuses. Final window is repair, accepted case reruns, export and2rehearsals; avoid new features. T-minus4hours: only fixes necessary to make bundle/query correct, then revalidate affected cases. These are planning buffers, not confirmed event rules.
Cut order: adaptive proposer; visual polish; generic callback/kill-switch demo; extra adapters beyond second; inline bonus if it displaces a complete control. Preserve honest source reconciliation, accepted measurement, required model/AICT integration and six artifacts. If9 has no accepted measurement basis, state2-control ceiling; no paper score compensates. If even1 control cannot be closed, submission not ready.

13. WHAT REMAINS OPEN AFTER THIS DESIGN
