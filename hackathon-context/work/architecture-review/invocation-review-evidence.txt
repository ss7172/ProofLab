Independent evidence and causality review

Scope: invocation contract against physical slides 12–15, 17, 19–26. Design review only; no integration or test result is treated as implemented. The contract correctly distinguishes decisions from assessments, observations from bindings, and detected breaches from successful prevention. The following commitments remain underspecified enough to permit misleading results.

1. HIGH — Completeness has no executable denominator contract (sections 3, 7, 11, 13).
“Independently justified expected population” is necessary but does not specify how a dynamic three-agent execution creates it. An adapter and its telemetry can disappear together, leaving a plausible closed run. A start/end pair alone does not prove all intervening work was observed. Control7 may pass a truncated population; Control16 may omit bypassed calls.
Fix: freeze event obligations by action type and phase, source coverage, and expected boundary send/receive pairs. Persist planned/dispatched work independently of the emitter where available; reconcile authoritative execution/usage inventories and scheduler expectations. Record source completion checkpoints, failed pagination, sampling, and unmatched/orphan events. Dynamic branches add durable obligations before execution. If no independent inventory exists, declare that gap and forbid a completeness-based SATISFIED result. Do not imply AWS/ServiceNow supplies such inventories until verified.

2. HIGH — Transport deduplication does not prevent duplicate accounting across sources (sections 6–7).
event_id handles redelivery, but gateway telemetry, provider usage and a pulled log can report the same actual call with different event IDs. Conversely, two real executions can share an erroneous propagated attempt ID. “Canonical source observation” does not define how either collision is resolved.
Fix: distinguish observation identity (source + source record ID) from execution identity and accounting-entry identity. Declare authoritative usage sources and precedence; attach multiple corroborating observations to one usage entry. Conflicting token totals, reused execution IDs or mismatched run joins remain visible reconciliation conflicts. Never silently deduplicate two actual retries; never sum corroborating observations as separate calls. Authenticated producers may supply facts, but cannot reassign an already-bound attempt to another run.

3. HIGH — “Invokes the model once” depends on an unverified downstream guarantee (section 6).
A crash after the model receives a request but before acknowledgement leaves dispatch ownership and actual execution ambiguous. A lease or database transaction cannot atomically commit a remote inference. The retained reservation protects budget, but does not itself establish exactly-once execution.
Fix: define RESERVED, DISPATCHING, OUTCOME_UNKNOWN and SETTLED transitions. Never redispatch an ambiguous attempt unless verified downstream idempotency makes that safe. An intentional retry gets a new attempt and reservation while the original liability remains. Reconcile both executions afterward. Describe duplicate suppression at the adapter boundary separately from downstream execution guarantees; list unavailable provider idempotency as a capability gap.

4. HIGH — Frozen policy does not specify valid policy (sections 3–5).
The proposal prevents callers choosing easier rules, but leaves unknown bundles, stale cached applicability maps, unsupported control versions and mid-run revocation undefined. A run could consistently use an obsolete policy and still appear compliant.
Fix: pin an authorized bundle containing applicability-map version, specification contents, effective interval and supported evaluator version. Validate it before governed dispatch; missing, invalid or unsupported bundles produce ERROR and no governed dispatch. Declare whether runs finish under their pinned version or are stopped at a policy transition; implement any necessary revocation signal outside the register’s live request path. Historical assessments retain their original policy and separately disclose policy-validity failures. Never substitute the current specification during a historical query.

5. MEDIUM — Control7 needs a precise timing population (sections 4, 7).
Completeness and timing use different denominators. “Consecutive” is undefined with parallel branches, reordered ingestion, missing events or cross-host clocks. Excluding unknown intervals could improve a failing result.
Fix: put coverage target, gap comparator, eligible ordered streams, exception allowance, clock/order basis and treatment of missing timestamps into the frozen C7 specification. Report expected/observed events and eligible/violating/unmeasurable gaps separately. Define zero-gap behavior; do not silently count it as a timing pass. Preserve missing intervals even when their duration cannot be measured.

6. MEDIUM — Control9’s run answer can overstate attribution (sections 3, 7, 12).
Window membership is explicit, but a run spanning several windows or none still has no answer rule. One window’s drift is not a measurement of each member run. Empty/missing windows and zero baselines also lack computation rules.
Fix: declare expected windows, membership/eligibility, metric direction, minimum observations and valid baseline domain. A run query lists all applicable window assessments and reports a declared aggregate only when justified; otherwise label the result window-scoped. Missing measurements remain INDETERMINATE. Report measurement satisfaction, monitor operation and alert delivery separately; silence is an observed response state, not proof of delivery.

7. MEDIUM — Offline reproducibility needs a complete assessment manifest (sections 7, 10–12).
Fix: export exact policy/mapping/baseline/expected-inventory versions, evaluator/test version, raw observations and bindings, assessment cutoff, source-completion state and superseded revisions. Distinguish event-time scope from ingestion-time “as of.” Each assessment references its exact input set. Late evidence creates a new revision rather than changing what an earlier answer meant. These are reproducibility requirements; cryptographic sealing remains out of scope.
