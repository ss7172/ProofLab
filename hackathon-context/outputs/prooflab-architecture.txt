PROOFLAB — FINAL DESIGN AFTER THREE INDEPENDENT AI REVIEWS
Proposal only. Current implemented controls: zero. Updated after engineering analysis; scores belong to independent judge reports, not this document.

Objective: An active assurance system for C-FM-01 that implements all three scored controls, challenges them with reproducible experiments, explains where the evidence stops, and lets a judge recompute any result without an LLM or the team.

Recommended design = candidate B: three-control deterministic engine, fixed executable adversarial suite, team-scoped ServiceNow integration and portable evidence/recheck. Target all three completed controls; one is the published minimum. Live token enforcement and a second running enforcement point are conditional bonus increments after control completeness, not prerequisites that may displace required evidence. The CLI is core; a browser UI is optional. These are substantial architecture capabilities. Use at most one bounded Nemotron assurance agent. Satisfy any mandatory team-owned model-use requirement early; enable adaptive test selection only after the core has completed controls and required artifacts. No independently deployed challenger service on the critical path. Challenger is an AI development/review role and a scripted evidence-challenge mode; a second runtime role remains optional.

- Approved workshop Strands/AgentCore deployment for one Nemotron test proposer. Verify the supplied subject agents and actual model IDs. Adaptive test selection remains gated behind the completed controls. Proposal service uses tools from an explicit allowlist.
- Shared model-gateway adapter and second zone/tool adapter use same versioned request/event envelope. Workshop model gateway identity is unverified: do not assume it is AWS AgentCore Gateway. If actual AgentCore Gateway is used and permitted, Lambda interceptors are a documented route; use available workshop hook otherwise. Read-only observer is not a preventive adapter.
- Preferred cloud mapping, conditional on enabled services: DynamoDB single-region conditional/transactional writes for reservations and idempotency; existing OTEL/CloudWatch acquisition; S3 raw records/spec/export bundles; one allowed backend deployment for query/UI. Reference checker detects arithmetic/interpretation differences, not false source records or institutional independence.

TRUST BOUNDARIES AND SOURCE AUTHORITY
Before implementing beyond first control, create a per-control source-authority map: population, authoritative expected-ID producer, why it sees every relevant action, observed source, run/attempt joins, clock domain, completion/watermark, access limitations, duplicate/late/out-of-order handling, gaps and bypasses. A derived expected list from the surviving observations is invalid. A run-close record is necessary but not sufficient. No independent source or complete interception => INDETERMINATE, never a completeness guarantee. No cryptographic tamper-proof claim.

CORE CONTRACT
Every envelope has schema_version, team_id, run_id, control_id, threshold_version, enforcement_point_id, actor_id, event_id, event_kind, occurred_at, observed_at, source_ref, provenance_class. Model records additionally attempt_id, input/output usage, cache-count semantics, model_version and call_outcome. Avoid counting both aggregate parent spans and leaf model spans. Execution decision ALLOW/DENY/ALERT is not control-test verdict. Test results include rule version, scope/window, denominator, actual measurement, exceptions, evidence sufficiency, control operation status and finding refs.
Provenance classes: LIVE_SUBJECT, AUTHORIZED_TEST, REPLAY, COUNTERFACTUAL_EXPORT, SYNTHETIC. UI and export display class. Synthetic/replayed results do not earn asserted live bonus.

CONTROL 16 RUNTIME PROTOCOL
1 Pin immutable spec contents and version in the run manifest when the run is admitted; registry stays out of each call path. Pass the frozen specification into the stateless evaluator as an argument, rather than hardcoding or storing thresholds inside the control. Reject mismatching event/spec versions. A new registry version must not create another budget bucket for an existing run.
2 Adapter obtains exact/justified request input bound and enforced output bound. Cache semantics and hidden/reasoning usage accounting must be defined for actual model. Unknown unbounded usage => no strict guarantee.
3 Coordinator reads versioned settled+reserved state; pure evaluator computes proposal. Atomic update reserves bound and creates a durable unique attempt/reservation record. Conditional failure rereads/re-evaluates with bounded retries. Do not dispatch model call without durable committed reservation; on ambiguous reserve response retrieve same attempt, never reserve blind twice.
4 Same logical attempt may retry admission idempotently but must not execute inference twice; explicit attempt dispatch ownership/state. If downstream idempotency cannot be verified, ambiguous dispatch remains held and is not auto-replayed. Actual new inference retry gets new attempt ID and reservation.
5 Model call executes under enforced bound. Settlement atomically updates both the attempt terminal state and run settled/reserved totals, with conditional idempotency. Only unused reservation releases. A stale worker cannot settle or release twice; conditional dispatch ownership cannot recycle ambiguous work after a lease expires. Unknown outcome remains outstanding until reconciliation. Expiry does not silently free possibly spent budget. Actual usage exceeding the reserved bound remains recorded in full, raises an invariant failure, and halts further admission; never clamp actual usage to the bound.
6 Critical reservation state is synchronous because it controls budget. Rich telemetry, registry reads and ledger export stay off path. Minimal reservation journal supports recovery; do not move evidence storage into evaluator.
7 Decision exported asynchronously with retry/drain/late rules; absent records remain gaps. S3/CloudWatch propagation not treated as synchronous proof.
8 Claim cap prevention only after verifying all governed calls intercepted, bounded, uniquely dispatched/settled and tested under concurrency. Otherwise ship honest detection. Known trustworthy subtotal >cap establishes breach even when additional usage missing; below cap+gaps stays indeterminate.

CONTROL 7
Manifest/producer sequence+acknowledged completion reconciled with actual crosszone events. Specify eligible gap pairs within known clock domains; do not subtract wall-clock timestamps across uncalibrated hosts. Cross-zone propagation joins separately checked. Coverage denominator based on expected, not received; duplicates/conflicts/unknown extra events visible. One missing record in cloned export demonstrates checker sensitivity, not actual runtime telemetry loss. An authorized live drop experiment is separate and requires safe isolation and permission.

CONTROL 9
Metric candidate: correctly diagnosed fault_id / eligible labelled scenarios, from a fixed held-out scenario suite with ground truth the agent cannot edit. Require a positive baseline; zero or insufficient baseline data leaves relative drift undefined and the branch NOT_ASSESSED. Freeze eligible/excluded scenarios, missing-label treatment and the basis for sample sizes and thresholds before seeing assessed results. Baseline measured before scored runs; dataset/model/prompt versions and comparable window membership frozen. Observation limit and allowed violating-window proportion separately declared. Minimum sample count and missing-window policy predeclared. Independently recompute windows; no zero denominator default. Record named alert recipient and actual pending delivery/response. If authoritative labels unavailable, use disclosed simulated reference corpus only if organizers accept its assessment scope, otherwise NOT_ASSESSED. LLM self-confidence or agreement is not accuracy.

ACTIVE TESTING
Hardcoded executable catalog first: normal run, retry burst, two-call budget race, duplicate delivery, dropped whole attempt, cross-run mislink, stale spec, missing metric window, degradation on matched scenario suite, delayed human response. Each test records scope, authorization, seed, action list, expectation and evidence references. Only team assets/cloned exports; no spontaneous network changes. Bounded Nemotron proposer may choose next existing test after core passes, with a declared episode limit, token budget, tool allowlist and validation. Its output is a proposed experiment; scheduler authorizes/runs and deterministic tests assess. Separate probe cost from subject-run measurement without hiding either. Benefit gate: reproduce one useful discrepancy not already selected by fixed initial campaign within allocated budget; if none, present it as exploratory, not proven better testing.

SERVICENOW

VERDICTS AND FINDINGS
For each selected control: rule satisfaction (SATISFIED/BREACHED/INDETERMINATE/NOT_ASSESSED), safeguard operation (worked/failed/unknown), evidence sufficiency, source provenance, scope. Missing-window coverage failure can coexist with unknown performance. Claim rollup: any substantiated breached requirement => full claim breached for assessed scope; no breaches but unassessed/indeterminate branch=>not established; satisfied only all declared required branches satisfied. No majority-vote LLM verdict. A passing new-run retest can close remediation with actual owner action where required, but never overwrites historical failure or changes the frozen rule.

Late evidence creates a new linked assessment revision with its as-of time; keep previous results, immutable historical specs and raw records available. A new result may correct a prior conclusion without rewriting its history.
