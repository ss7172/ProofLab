RUNTIME AND LATENCY

INDEPENDENT RUNTIME / LATENCY REVIEW — NEMOTRON EVIDENCE AGENT

Source basis: current detailed architecture, supplied NVIDIA transcript excerpts and slides. No other reviewers' reports consulted. The transcript supports meaningful Nemotron agent use but does not establish endpoint IDs, JSON-schema enforcement, token limits or inference latency. Existing cloud integrations remain unverified.

RECOMMENDATION
Promote a single Nemotron Evidence Investigator into the normal evidence-query workflow. It reads authorized heterogeneous records, extracts cited candidate relationships from text/tool output, requests bounded corroborating records, and assembles an intelligible evidence dossier. Deterministic adapters still ingest structured usage and identity fields; deterministic tests own arithmetic, completeness and verdicts. This gives NVIDIA a substantive extraction/retrieval role without making an LLM a token accountant or inventing missing run IDs.

Use one bounded orchestration job, not collaborating recursive agents. Background ingestion prepares source records and indexes; foreground consolidation operates against an explicit snapshot. A relational association table supports many-to-many evidence links; a new graph database is unnecessary.

TYPED INTERFACES
All tools derive team/identity/authorization server-side; every result carries snapshot_id and source references.
1 open_snapshot(scope, controls, as_of) -> snapshot_id, applicable_specs, expected_sources, source_watermarks, gaps, allowed_record_ids, limits. The controller owns this operation and control applicability.
2 search_evidence(snapshot_id, typed_filters, cursor, limit) -> records, next_cursor, truncated, source_status. Filters use run/action/attempt/window, source and event types; no arbitrary SQL, URLs or cross-team queries.
3 read_evidence(snapshot_id, record_ids, byte_limit) -> immutable fragments with JSON pointers or text offsets, exact source version and authority classification. Reject IDs outside the authorized snapshot.
4 propose_links(snapshot_id, candidates[]) -> accepted_candidates, rejected_candidates, reasons. Candidate schema: source_ref, target_ref, relation_enum, control_context, supporting_locators[], extracted_values, uncertainty. A schema-valid candidate is not an authoritative binding.
5 assess_control(snapshot_id, control_id, scope) -> deterministic measurements, denominators, missingness, requirement/operation/evidence states and exact input references. Agent cannot change thresholds or supply its own arithmetic as the result.
6 build_dossier(job_id) -> immutable dossier revision with authoritative evidence, candidate links, deterministic assessments, cited explanation and job status. Controller finalizes; it does not rely on the model deciding that work is complete.

SEMANTIC EXTRACTION BOUNDARY
An LLM can extract a ticket's mention of a tool result, identify related incident descriptions, classify a narrative as a possible alert response and propose relationships across these records. It cannot certify actor identity, delivery, run membership, usage or complete coverage from similarity. Validate JSON types/enums, source existence, cited spans, exact extracted identifiers, tenant/run scope and temporal compatibility. Promote a link to authoritative only when its declared source/join rule corroborates it; otherwise retain a visible candidate. Self-reported confidence or a second LLM vote is not corroboration. Conflicting candidates remain visible. Preserve model, prompt, extractor version, input snapshot and output provenance.

ONE-MINUTE CONTRACT
Promise a bounded response attempt, not acquisition of all evidence within60seconds. Define the target as: “For a declared maximum-size assessed scope with indexed evidence available at the cutoff, return a consolidated dossier within60seconds; otherwise return a partial/deadline result identifying missing sources.” Source freshness, completeness and response latency are separate measurements. Do not call partial output a complete one-minute success.

Illustrative controller budget, to benchmark against the actual enabled model:0–10seconds pin snapshot and parallel bounded retrieval;10–35seconds one extraction/corroboration round;35–45seconds validation and deterministic assessment;45–55seconds optional synthesis;55–60seconds finalization margin. At most two model calls, fixed tool-call/result-byte limits and no autonomous retry loop. These numbers are proposed allocations, not measured capabilities. If extraction overruns, skip synthesis and render a deterministic source table plus clearly unavailable semantic enrichment. If even minimum source scope is unavailable, report INCOMPLETE rather than fabricate conclusions.

The controller enforces remaining-time deadlines independently of the model. Cancellation may not terminate a remote inference: keep its budget liability and record late completion. Late records/results produce a new dossier revision, never silently mutate the delivered snapshot. ServiceNow writes/readback run asynchronously and have their own actual delivery status. Baseline collection and running fresh diagnostic scenarios do not belong inside the60-second query budget.

BUDGET AND SELF-OBSERVABILITY
Create assurance_job_id linked to subject_run_ids, with a separate declared query budget, attempts, tool timings, provider usage, input/output bytes and truncation. Show subject-run spend and assurance spend separately and in total. Do not silently exclude the new agent from the declared control scope: confirm whether organizer rules include assurance calls in the governed run cap, and apply that scope consistently. Reuse deterministic admission/accounting where supported. Agent telemetry is recorded through code and never triggers another evidence-agent job automatically; the snapshot excludes the current job's newly emitted records. This avoids self-auditing recursion without hiding cost.

TOP RELEASE GAPS
First verify the actual permitted Nemotron endpoint and model behavior, deploy the bounded investigator on approved Strands/AgentCore or ServiceNow integration, and prove authenticated tool access. Benchmark realistic scoped payloads, concurrent queries and cold starts; report distribution, timeout rate, complete-dossier rate and source age, not one best run. Test prompt injection in source text, fabricated IDs, wrong-tenant matches, missing whole sources, invalid model JSON, ambiguous relationships, late results and exhausted budgets. Model-generated text cannot call arbitrary tools or modify policy. A fallback preserves the original deterministic judge query, but only successful real Nemotron extraction demonstrates the newly requested AI capability. Local UI remains a client; inferred cloud permissions and endpoint names must not appear as implemented facts.

FINAL SYNTHESIS CHECK
Reviewed work/nvidia-review/nvidia-architecture-v1.txt independently. The design is conditionally implementable and meaningfully uses Nemotron. Four runtime ambiguities need explicit protocol text before implementation:

1. HIGH — Make the two-call choreography and tool budget executable. “Permitted follow-up reads” must not imply an adaptive third model turn. Define call1 as optional planning, then one bounded host retrieval stage, then call2 as extraction/composition; later requests are unresolved or a separately timed job. State whether the six invocations count only agent-requested reads or also open_case, assessment, candidate submission and assembly. Pagination, retry attempts and batched internal I/O need their own bounded accounting; they cannot become an uncounted backdoor to unlimited retrieval. The simpler contract exposes list/get as model tools and keeps scope, assessment and finalization host-owned.

2. HIGH — Bound background model extraction separately and exclude recursive inputs. Two foreground calls do not cap continuously running Lightning extraction. Give background jobs their own cost/concurrency limits, source-version/extractor-version deduplication and priority below active judge queries. Explicitly exclude investigator-origin prompts, outputs and derived proposals from automatic extraction unless a separate user-requested bounded inspection authorizes them. “Do not launch another investigator” alone does not prevent the background extractor from processing its own output indefinitely.

3. HIGH — Define reads after snapshot freeze. Reads may materialize only exact source versions already referenced by the frozen snapshot. Newly discovered records or changed remote content must not enter that case silently; start a new snapshot/revision. Foreground-derived proposals may reference frozen inputs but do not advance source completeness. Distinguish unavailable frozen content from genuinely absent evidence. This preserves offline reproducibility and prevents late source reads from changing denominators halfway through a query.

4. MEDIUM — Include admission queueing and publication in deadline accounting. Start the accepted-job timer at request receipt/admission, not after waiting for a model slot. Reject overload promptly or return the explicit degraded status within the same deadline; never hide queued time. Reserve capacity for deterministic fallback and account remote work that continues after cancellation. One thousand generated tokens may be insufficient for twenty cited extracts plus a brief; validate actual bounded response size and classify truncation honestly.

The principal unverified gates remain approved endpoint/tool-schema behavior, exact input/output/reasoning limits, authenticated source access, immutable source-version retrieval, real latency under concurrency/cold starts, and complete input populations. No numerical rescoring or live verification is implied.

EVIDENCE AND ASSURANCE

INDEPENDENT NVIDIA EVIDENCE/ASSURANCE REVIEW

Recommendation: make one active Nemotron evidence agent a core product component. It performs source-cited extraction, proposes cross-source relationships, investigates contradictions using bounded retrieval, and assembles the control/run/window evidence packet. This replaces the optional last-stage test proposer as the principal model role. Deterministic tests retain arithmetic and verdict authority. This is substantial evidence work; calling a model only to restate a precomputed verdict would not meet the user’s requested role.

Source basis: detailed architecture sections3–7 and10–11; slides physical14–15 distinguish evaluator, ledger and tester. Transcript excerpts chars35584–38304 require Nemotron in agents, while chars17344–19489 and24144–25907 allow extensions/adversarial use. These establish a use requirement, not endpoint availability, extraction reliability or one-minute latency. Confirm actual workshop model IDs, hosting, data permissions and limits; no specific variant’s speed is assumed.

PROPOSED PIPELINE
1. Resolve the question into a candidate control/scope query; validate against authenticated tenant scope and frozen applicability. Ambiguous run/window selection produces explicit alternatives, not a guessed merge.
2. Capture an immutable assessment snapshot: source versions, event-time scope, ingestion cutoff, per-source pagination/checkpoints, policy/baseline versions and independent expected inventories. New arrivals create another revision. A snapshot freezes what was retrieved; it does not establish source completeness.
3. Deterministic adapters extract reliable structured fields. Nemotron extracts assertions from incident notes, free-form agent explanations and unfamiliar annotations; it identifies entities, candidate handoff/usage/alert relationships and conflicting statements. Give it bounded read-only fetch/search tools over the snapshot and authorized sources, so it can investigate missing support rather than summarize only its initial context.
4. Emit structured candidates: candidate_id, subject/object source IDs, proposed relation, typed value, exact supporting spans/JSON pointers, qualifiers, extraction version and uncertainty. Each candidate preserves original bytes and never overwrites an observation. Maintain CANDIDATE, VALIDATED or REJECTED status plus reason; confidence is advisory.
5. Validate source existence, cited offsets, types, units, tenant/run/spec identity, event chronology where defensible, relation allowlist and declared source authority. Exact citation presence validates provenance, not semantic entailment. For authoritative fields use exact parser/identity rules or an independently approved extraction procedure. Ambiguous semantic matches remain candidates; a second model’s agreement does not automatically promote them. A critical unresolved candidate leaves the relevant assessment indeterminate.
6. Compute assessments over validated inputs, then let Nemotron construct a cited explanation and explicit relationship view. Render authoritative numbers/statuses directly from the assessment object; reject narration that contradicts it. Display candidate links separately from validated joins.

MANY-TO-MANY AND TRUTH BOUNDARIES
One observed call can support C7 recording and C16 usage through separate bindings, while one assessment uses many records. A C9 window references multiple runs. Semantic similarity or close timestamps cannot establish identity, causality, completeness or accounting deduplication. A model-proposed “probably the retry” is investigative context until an authoritative join supports it.
Only declared authorities establish usage totals, expected-event populations, ordered timing pairs, baseline labels, applicable policies and source completion. Never turn an extracted prose claim “all calls logged” into a denominator. Preserve contradictory totals and unresolved identities; do not average, choose the most fluent narrative or count each corroborating source as another execution. Known trustworthy overspend can prove breach despite missing usage; apparent underspend cannot prove completeness.
Nemotron may extract a diagnosis from free text, but C9 ground truth must remain independently supplied. Prefer canonical structured predicted_fault_id for scoring. Model-generated labels, self-confidence or the same model judging its own explanation cannot establish diagnostic accuracy. Any unavoidable semantic scoring procedure requires separate declared validation and disclosed limitations.

SECURITY, LATENCY AND REPRODUCTION
Treat source text as untrusted data, including “ignore policy” instructions. Retrieval authorization and tenant filters execute outside model control; scope cannot widen through a tool argument. Agent tools cannot mutate policy, usage, raw evidence or remote findings. Whitelisted reconciliation requests may be queued separately. Record assurance model usage under its own explicit budget/run with an assesses relationship to subject runs; do not hide cost or recursively ingest current agent narration as subject evidence.
One minute is the user’s target; the supplied judging requirement is two minutes. Declare supported snapshot size and test cold extraction separately from warmed queries. Example engineering budget:5s snapshot/retrieval,30s bounded parallel extraction,10s validation/tests,10s packet assembly,5s reserve. These are targets, not measured guarantees. Enforce deadlines and return truthful partial/indeterminate results on timeout; count these as unsuccessful complete-answer attempts. Report completion rate and latency together.
Export raw snapshot, candidates including rejected ones, validation decisions, exact assessment inputs, prompts/model IDs/settings, tool traces, model outputs and versioned checkers. Offline replay consumes saved outputs and rechecks accepted facts; identical model regeneration is not required or promised.

REQUIRED FAILURE TESTS AND ACCEPTANCE
• Fabricated source ID, altered quote, negation reversal and plausible unsupported link: none becomes authoritative; rejected reason visible.
• Two tenants sharing run IDs plus embedded exfiltration/tool instructions: zero cross-tenant retrieval or unauthorized action.
• Duplicate gateway/provider usage, retry with missing parent, conflicting totals: one authoritative charge per actual execution; conflicts retained; no false under-cap pass.
• Entire missing stream, partial pagination and absent completion checkpoint: no model-inferred completeness; expected gaps survive.
• Late arrival during extraction: answer references one snapshot; later evidence creates a revision.
• Wrong/ambiguous free-text diagnosis and tampered baseline labels: no self-generated ground truth or concealed exclusions.
• Model unavailable, invalid JSON and deadline overrun: explicit incomplete extraction; deterministic known facts remain accessible.
• Offline recheck: identical accepted inputs, totals, denominators and verdicts without a model connection.
Before demonstration, freeze a reviewed extraction benchmark containing these cases. Require zero unsupported authoritative facts/joins and zero false SATISFIED results on that suite; report extraction precision, recall, abstention and complete-answer latency. Demonstrate useful extraction/relationships absent from structured adapters, with correct citations. A zero-error test suite is evidence of tested behavior, not a universal accuracy guarantee.

2. THE GAP AND MINIMAL SUBSTANTIVE MODEL ROLE
The current design uses NVIDIA primarily through supplied subject agents and an optional last-stage test proposer. It does not specify team-owned extraction or evidence synthesis, validate that work, or measure its latency. The new user request makes that a core product feature rather than optional decoration.

Implement one bounded Nemotron Evidence Analyst in the permitted Strands/AgentCore environment, with two model stages in one controlled workflow:
A. Extract candidate observations from a bounded selection of actual unstructured incident notes, agent explanations and tool-result text. Output typed candidates: assertion_type, entity/action/attempt candidates, exact source_id and source span, time mentioned, ambiguity and suggested control relevance.
B. After deterministic reconciliation and control tests, synthesize a concise explanation of the result, supported observations, contradictions, missing evidence and the next specific inspection step. Cite immutable source/assessment IDs. The explanation should identify why the evidence supports or fails to support the claim, not merely restate a colored status.

Example: a note says “retried the diagnostic request,” while the authoritative attempt inventory contains only one known attempt and reports incomplete coverage. The model can extract the retry assertion and highlight a discrepancy; it cannot invent a second provider execution or token count. Exact source-span validation proves the note said it, not that the retry occurred.

The extraction improves discovery and navigation; authoritative structured telemetry remains directly parsed. The model never creates expected populations, ground truth, cap arithmetic, final verdicts or admission decisions. Schema/citation validity alone does not prove semantic extraction correctness. Unverified critical identities remain unresolved candidates. Render authoritative verdict/measurement fields from the deterministic assessment, separately from model prose.

Tool calling is useful only if its actual serving configuration works; a host-controlled two-call pipeline is sufficient and simpler. This is a proposed design choice, not an organizer requirement to use a specific Lightning ID.
Optional Super: ambiguous, complex cross-source synthesis after a benchmark demonstrates worthwhile quality improvement within the same latency/cost budget. Do not make it the automatic second hop on every query.
