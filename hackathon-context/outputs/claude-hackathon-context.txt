OBJECTIVE AND PRODUCT
Build an evidence-backed assurance application around the supplied telecom agents. It should detect and explain control violations, bind authentic source evidence to dated control specifications, retrieve a coherent case for a judge, and demonstrate the required alert/named-recipient evidence through the accepted governance path. Record an actual response or adequately observed silence; a human reply is not required. Claim remediation only when a corrective action and relevant passing retest actually occurred. Improving the reference agents' ambiguous S2 behavior while preserving S1/S3 safety is a workshop-emphasized demonstration goal, scheduled as optional differentiation after required controls. Produce a reproducible Evidence Pack in the event's team S3 bucket.

Our chosen scope is C7 event recording/coverage/timeliness, C9 operational performance drift and C16 whole-run model-token budget. The guide permits at least one of these and emphasizes C16; three controls are our competitive ambition, not a claim that the organizer mandates all three. Advanced quality means correct boundaries, correlation, missing-data handling, late revisions and reproducibility. It does not require sixteen microservices.

The proposed deployable shape is deliberately small:
  Supplied agents on AgentCore -> shared modaas-agw -> approved Bedrock Nemotron models
  Supplied agents -> governed MCP/tool routes -> AgentCore Gateway/Lambda where configured
  CR status + TMF639 + ledger + gateway/PDP logs + CloudWatch spans/metrics
       -> permissioned host collectors -> raw files + SQLite normalization/checkpoints
       -> deterministic C7/C9/C16 evaluators -> assessments/evidence bindings
       -> bounded approved Nemotron investigator -> host validation -> cited EvidenceCase
       -> local/read-only judge UI and portable pack
       -> authorized ServiceNow adapter/outbox/readback if instance and contract exist
       -> supplied submit.sh -> event team S3 bucket -> verified judge-readable package.

PROPOSED STORAGE/PLACEMENT, NOT A VERIFIED PLATFORM CAPABILITY: start the Python evidence/query process in the Workshop IDE host using its existing role; use local files and SQLite transactions for the team application's state and outbox. Keep data off ephemeral AgentCore memory as the sole durable store. The participant laptop may edit or display outputs but must not be the judges' only evidence source. IDE host availability, filesystem durability, port access and read permissions must be tested. A private local UI and exported static view avoid inventing a public hosting grant. An AgentCore investigator receives a bounded evidence packet in its invocation payload, or calls explicitly authorized read tools; it cannot magically read IDE files. Do not create DynamoDB, S3 pod roles, public APIs or production infrastructure just because they appear in an earlier conceptual drawing.
