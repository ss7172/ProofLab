1. DEPLOYABLE SHAPE: ONE PYTHON DISTRIBUTION, SMALL NUMBER OF ENTRY POINTS
A. Platform adapters: shared-model gateway adapter, zone-boundary adapter, telemetry source connector and ServiceNow connector. Install/configure only through supported workshop hooks. First second-point target is gatewayB handoff; use a permitted tool boundary ifB cannot be modified, or a read-only source with an honest observation label. Different adapter code is expected; control/evidence logic remains unchanged.
B. Assurance backend: one shared package, entry points for synchronous admission and asynchronous collection/window assessment/export. Run inside permitted AWS compute when live enforcement requires reachability. Prefer an allowed gateway function/wrapper for admission and an allowed scheduled/event worker for assessment. Do not assume permissions for Lambda, a long-running container, scheduler or a public API. Compute choice is closed by the first capability gate. If unavailable, retain the same pure tests in an offline read-only package and downgrade live claims.
C. ServiceNow team configuration/integration: team-prefixed asset connection plus real permitted alert/finding/owner workflow. It is an external governance integration, not a second copy of the control engine or an assumed kill switch.
D. Judge client: local CLI with optional small HTML UI reading the same query results. Authenticated cloud evidence download or portable local bundle; no laptop dependency in the inference path. No public tunnel or third-party hosting assumed.

Preferred storage if enabled: single-region DynamoDB for atomic budget/run/attempt/minimal-outbox state; S3 for immutable policy versions, raw observations and exported bundles; local SQLite index generated from bundle JSONL for fast offline queries. These are proposed mappings, not verified workshop entitlements. A conditional-write/transaction-capable permitted store can replace DynamoDB through the state repository contract. S3/SQLite never substitutes for cross-worker atomic admission state. Existing OTEL transport/source is reused; add no new bus merely for diagram symmetry.

Proposed package modules, not created files:

3. CANONICAL DATA AND KEYS
All records include schema version, team, provenance class and stable source references where applicable. Provenance: LIVE_SUBJECT, AUTHORIZED_TEST, REPLAY, COUNTERFACTUAL_EXPORT, SYNTHETIC. Exact schemas should be encoded during implementation from these required fields; no cloud table names are asserted.
PolicyBundle key(team,bundle_version): immutable spec contents, applicability version, effective interval, evaluator versions, control owners, freeze time, baseline/dataset references, declared source/completion rules. Reject missing/unsupported bundles and bundles expired for new-run selection when opening governed work. Proposed default: ordinary releases affect new runs; active runs retain their exact pinned contents up to their declared run deadline. Selection expiry does not by itself terminate permitted pinned continuation. Declare hard execution cutoffs and urgent revocation separately, using trusted runtime state/time and an authenticated stop mechanism at verified inline points, not per-call register reads. Preserve already-sent liabilities and all evidence; record stop propagation gaps. Historical queries continue to load the original exact bundle/specification/evaluator even after selection expiry or revocation. Publishing a new bundle neither alters historical assessments nor resets or splits an existing run budget. C9 window eligibility/membership rules, baseline, scorer and applicable specification are frozen before assessed cases; do not silently combine incompatible cohorts.
Run key(team,run_id): owning scope, bundle_version, opened_at, status OPEN/ACTIONS_CLOSED/EVIDENCE_FINAL, version/CAS, settled_tokens,reserved_tokens, declared expected source set, late-data deadline and capability snapshot. Admission/closure share conditional concurrency checks.

Obligation key(team,run,action_or_attempt,event_kind,phase): created_by independent expected-work authority, expected_source, expected_stream_id, clock_epoch, authoritative_sequence_slot and predecessor_slot (or an independently supplied expected-pair inventory), causal parent, eligibility, deadline, cancelled_reason if proved never dispatchable. Expected order/pair membership cannot be derived only from surviving observations.
Observation key(team,source_instance,source_record_id,source_revision): event_id, run/action/attempt links, type, actor, event_time, ingestion_time, source sequence/clock domain, payload/source ref. Multiple observations can corroborate one execution. Conflicting IDs or totals retained, never silently merged.
UsageEntry key(team,provider_source_namespace,authoritative_execution): resolved run/attempt associations, input/output and defined cache/reasoning accounting, authoritative source, corroborating observations, revision. Never sum aggregate parent and leaf usage. A reused attempt ID for two actual provider executions is a conflict to resolve, not permission to drop one charge. Source namespaces include the relevant instance/account/endpoint/region/session as required for uniqueness. If two runs claim the same execution, retain the conflict and resolve scope before attributing it; do not create two charges by using run_id in the execution uniqueness key.
EvidenceBinding key(team,binding_id,binding_revision): exact observation/usage/window record and revision +control_id+spec_id/version+run/window+role, accepted-input/validation provenance. One observation may support7 and16. Charge accepted usage once per authoritative execution; never sum duplicate fact rows produced by many-to-many binding joins.
Window key(team,cohort,window_id): baseline_id, scenario membership, expected count, metric/scoring version, time interval, closure/source checkpoints, valid result refs and missing set.
Assessment key(team,control,scope,revision): exact input refs/versions, event-time interval, as_of ingestion cutoff, expected/observed denominators, measures, exceptions, requirement verdict, operation state, evidence sufficiency, provisional/final status, gap refs and supersedes.
Alert/Finding key(team,control,assessment,kind): local idempotency identity, named owner/recipient, delivery attempts, actual remote record ID, PENDING/DELIVERED/FAILED delivery, separate response state, remediation/retest references. No fabricated human acknowledgment.

Admission exposure: F is finally settled actual usage from completely resolved admission units; H holds the full aggregate bound of each unresolved unit. New boundB requires F+H+B<=cap. Estimates/averages and unverified output limits are not trustworthy bounds. Unknown or unbounded bypass/retry exposure prevents a strict-prevention claim.
State machine:
NONE ->RESERVED: authorized point; runOPEN/unhalted; correct effective pinned bundle; matching immutable request; atomic capacity check F+H+B<=cap; create unique attempt +reserve +minimal decision/outbox. ALLOW follows a known durable commit. Ambiguous commit/reply resolves the same identity; no fresh-attempt workaround or direct provider fallback. Admission decisions remainALLOW/DENY/ERROR; unresolved commit returnsERROR with resolution pending and no dispatch permission.
Existing same admission ->existing record: identical request identity returns same state, never grants a second dispatch. Conflicting payload rejects.
RESERVED ->CANCELLED: only proven undispatched and no previous dispatch claim; atomically release reservation, record reason. DENIED is a recorded no-reservation decision, not a provider execution.
RESERVED ->DISPATCHING: atomically require runOPEN/unhalted and the valid authorized execution context while conditionally claiming attempt ownership once; the trusted dispatcher sends the exact bounded model request. A duplicate ALLOW receipt grants no second dispatch right. Changing prompt/model/output options invalidates prior admission. The state transaction and remote provider send are separate;DISPATCHING proves ownership, not receipt/execution. No exactly-once provider guarantee is implied.
DISPATCHING ->OUTCOME_UNKNOWN: ambiguous remote send or lost response; hold liability. Expired lease cannot justify redispatch. Repeat downstream only if verified provider idempotency guarantees it; otherwise a deliberate fresh inference is a new attempt+reservation while old liability stays.
DISPATCHING/OUTCOME_UNKNOWN ->SETTLED: first resolve every execution reachable under the admission, authoritative final usage and absence of unaccounted upward liability; then atomically transition once, add final actual toF, remove the whole bound fromH and journal the update. A first response, partial usage or one hidden execution's final report is insufficient. Until finality is established, retain the entire bound. If source finality is unavailable, keep it charged against admission capacity for the rest of the run instead of recycling apparent savings. Genuine late outcomes can resolve unknowns, but a reporting deadline alone cannot.
SETTLED ->versioned correction: preserve both source assertions and revisions; apply an accepted authoritative replacement once under the reconciliation rule, never sum duplicate reports or replay stale corrections. Actual>bound retains at least the true known exposure, exposes prevention failure and halts new admission. Any upward correction after verified-final settlement invalidates the finality premise and halts new admission pending resolution even if still within the original bound. Example:8000 prior+bound1500, prematurely release on provisional1000, then admit another1000; first execution corrected to1500 permits10500actual despite the original bound holding. Existing liabilities remain recorded/held and authorized work may still complete; stopping new admission cannot undo an overshoot or guarantee the cap for already-authorized work.
OPEN ->ACTIONS_CLOSED atomically stops new admission and dispatch ownership claims. Claim transactions check the same run state. If a claim commits before closure, its worker may physically send afterward; that is pre-close authorized work and remains a liability. Closure does not cancel sent requests or establish a physical no-send-after-close guarantee. Such a stronger guarantee needs verified provider-boundary coordination; another pre-send read does not eliminate the race. A recovery worker cancels remaining RESERVED attempts only through a conditional proven-undispatched transition excluding a winning claim, releasing each bound once. EVIDENCE_FINAL is an as-of evidence cutoff after required source reconciliation or explicit gaps, not proof every remote action finished. Unknown liabilities remain disclosed/held; final can beINDETERMINATE. Continue ingesting all late actual usage. A post-close send timestamp alone does not prove unauthorized new work; correlate authorization, send and outcome. A new claim accepted after closure is a coordination/bypass failure and is retained/flagged.

Datastore-neutral admission transaction preconditions: team ownership, run version/status, authorized bundle, absent attempt or exact idempotent match, sufficient exposure. Writes: run reserved+bound/version++, attemptRESERVED, minimal transition/outbox. Evaluate capacity is a pure function; coordinator owns retries/CAS. Settlement transaction checks attempt not already settled and source authority, updates run+attempt+transition together. Do not separately ConditionCheck and Update the same DynamoDB item; put conditions on writes if that store is used.
Minimal durable journal belongs to coordination; rich ledger export remains async. Store unavailable =>deny governed admission with explicitERROR, adapter recovery if possible, expose any unrecorded gap. ALLOW must never precede durable reservation. Dispatch identity, source bounds, retry coverage and bypasses must be verified before claiming strict prevention. Verify hidden SDK/provider retries as actual potentially billable executions; disable them where permitted or intercept/account for each execution and its bound. One logical SDK call is not assumed to mean one provider inference.
Done gate: full3-agent/retry accounting, unchanged dated cap, passing and actual/accepted breaching run, conflicting/duplicate/missing-usage cases, reproducible export. Preventive bonus separately requires verified hook+bound, live deny, concurrent race and crash tests. A denied attempt is not an actual breached run.

M12 accepted-fact changes invalidate dependent control/window/population/claim assessments and caches through recorded dependencies. Recompute affected scopes before reusing their results; context-only acceptance need not change arithmetic. Concurrent revisions validate an explicit base and publish consistently; source reconciliation remainsM05, pure calculationsM07–M09, live settlementM10.
