The slide’s actual order

Completion first. Quality next. Extras afterward.

01How many?

One completed control is the minimum. Two precede one; three is the full set. An elaborate interface cannot compensate for an unfinished control.

02How well?

Answer a selected control/run/window within two minutes. Show the frozen rule, calculation, underlying records and gaps. Keep the evaluator stateless and register off the live path.

03What extra?

Prove a real inline decision, executed adversarial tests and a working second enforcement point using unchanged control logic. Planned demonstrations earn no demonstrated bonus.

A completed control may report a breached requirement. The control, test and evidence can work correctly while the governed run fails. Preserve that failure and any later passing retest.

Prescribed controls · proposed implementation

Each control needs its own measurement contract.

All three share policy, identities, evidence and query infrastructure. Each has a different expected population and test. Select a control to inspect the specific completion gate.

AIA-LOG-001

Control 7 — prove coverage and test event timing.

Build: independent expected-event obligations, normalized observations and coverage/timing reconciliation across the declared three-zone scope.

Expected work includes run lifecycle, model request/admission/dispatch/outcome, real retries, handoff send/receive and declared tool actions. An alternative terminal outcome occupies one required slot.

coverage = matched required obligations / all required obligations

Expected adjacent timing pairs come from an independent ordered stream inventory. Use sequence and valid same-clock epochs; do not subtract unrelated host clocks.

Review-driven safeguard: losing an entire attempt or stream cannot make the denominator smaller. A missing middle event leaves both expected adjacent pairs unmeasurable.

With known pair population P, violations K and unmeasurable pairs U, violation share lies between K/P and (K+U)/P. Unknown pair membership means no defensible bound. Empty populations are NOT_ASSESSED.

Complete when: accepted scope, dated coverage/gap/tolerance rules, actual pass and breach, missing/reordered/duplicate tests, source-backed query and export all exist.

AIA-ARC-006

Control 9 — a measurable diagnosis experiment.

Chosen proposal: exact-match single-fault diagnosis accuracy using accepted scenario labels. Freeze output mapping, timeout, cohort mix and scenario membership.

Separate baseline from assessed scenarios. All eligible baseline outcomes must be known; positive baseline B = correct / eligible cases. Missing telemetry is UNKNOWN. Proven wrong answers or timeouts score zero.

window drop = 100 × (baseline − window accuracy) / baseline

Compare fully measured, comparable windows with the predeclared drop limit; separately test allowed violating-window share and measurement coverage.

Review-driven safeguard: missing cases cannot become an observed-only baseline or zero drift. Every measured window over its limit generates an alert, even when an aggregate tolerance permits that exception.

Evidence links scenario → run → window → assessment → actual ServiceNow alert and named recipient. Pending delivery is not delivered; human silence stays visible.

Complete when: accepted labels, justified sample/threshold policy, frozen baseline, actual pass/breach windows, missing-window test, real alert status and reproducible exports exist.

Largest eligibility risk: label availability and organizer acceptance of the declared benchmark scope.

ACN-COST-001

Control 16 — complete accounting, then prevention.

Completion foundation: sum authoritative input/output usage for every actual model execution across all three agents and retries. Define cache/reasoning accounting; never double-count parent spans and leaf calls.

A known subtotal above the cap proves overspend. A subtotal below the cap with missing calls cannot prove compliance. Reservations describe exposure, not actual usage.

admission: settled + reserved + request bound ≤ cap

Optional prevention atomically reserves capacity before allowing dispatch. Request identity and the external dated policy stay fixed.

Review-driven safeguard: run closure races atomically with both admission and dispatch. Ambiguous remote outcomes retain liability; expired leases never justify blind redispatch.

Hidden SDK/provider retries must be separately accounted and bounded. Real new inference retries get new attempts; duplicate transport deliveries do not.

Complete when: whole-run usage is reconciled; unchanged dated cap; actual/accepted passing and breaching cases; duplicate/conflict/missing-usage tests; query and export.

Bonus gate: real bounded inline refusal plus concurrency/crash tests. A denied call is not an actual overspend case.

No final thresholds are declared yet. Values such as 10,000 tokens, 5 ms and 10% are teaching fixtures. Choose justified parameters and named owners, date and freeze them before assessed runs.

0. PURPOSE AND OFFICIAL ORDER

C-FM-01: during fault resolution, the three collaborating agents meet declared event-recording, drift and token-spend requirements. Target all3 controls completed end to end:7 AIA-LOG-001,9 AIA-ARC-006,16 ACN-COST-001. Minimum1; complete2 precedes1, complete3 is the full set. Quality decides among comparable coverage; extras then differentiate. The new attached slide is the judging rubric, printed27 (physical25 in the full deck). Actual demonstrated state remains0/3. Existing HTML explanations are design documents, not live applications.

Completion of a control means its declared scope, dated justified rule, actual mechanism, independent population/measurements, passing and genuine or organizer-accepted breaching cases, reproducible test and export all exist. A fully working detector can report a breached requirement: 'control complete' is not the same as 'all runs green'. A named gap does not complete an unmeasurable branch.

1. DEPLOYABLE SHAPE: ONE PYTHON DISTRIBUTION, SMALL NUMBER OF ENTRY POINTS

A. Platform adapters: shared-model gateway adapter, zone-boundary adapter, telemetry source connector and ServiceNow connector. Install/configure only through supported workshop hooks. First second-point target is gatewayB handoff; use a permitted tool boundary ifB cannot be modified, or a read-only source with an honest observation label. Different adapter code is expected; control/evidence logic remains unchanged. B. Assurance backend: one shared package, entry points for synchronous admission and asynchronous collection/window assessment/export. Run inside permitted AWS compute when live enforcement requires reachability. Prefer an allowed gateway function/wrapper for admission and an allowed scheduled/event worker for assessment. Do not assume permissions for Lambda, a long-running container, scheduler or a public API. Compute choice is closed by the first capability gate. If unavailable, retain the same pure tests in an offline read-only package and downgrade live claims. C. ServiceNow team configuration/integration: team-prefixed asset connection plus real permitted alert/finding/owner workflow. It is an external governance integration, not a second copy of the control engine or an assumed kill switch. D. Judge client: local CLI with optional small HTML UI reading the same query results. Authenticated cloud evidence download or portable local bundle; no laptop dependency in the inference path. No public tunnel or third-party hosting assumed.

Preferred storage if enabled: single-region DynamoDB for atomic budget/run/attempt/minimal-outbox state; S3 for immutable policy versions, raw observations and exported bundles; local SQLite index generated from bundle JSONL for fast offline queries. These are proposed mappings, not verified workshop entitlements. A conditional-write/transaction-capable permitted store can replace DynamoDB through the state repository contract. S3/SQLite never substitutes for cross-worker atomic admission state. Existing OTEL transport/source is reused; add no new bus merely for diagram symmetry.

Proposed package modules, not created files: contracts/ schemas and enums; policy/ validation and applicability; adapters/ platform translations; runtime/ admission, dispatch, settlement; sources/ obligation and usage reconciliation; controls/ c7,c9,c16 pure tests; governance/ ServiceNow delivery; query/ query, export and reference recheck; scenarios/ fixed authorized campaigns. No graph database, extra orchestration platform, cryptographic ledger or multiple assurance agents. Retain/verify supplied Nemotron usage; custom agents follow required workshop model/hosting rules. Optional bounded Nemotron test selection is the last increment, not an exemption from model requirements.

2. NORMALIZED CONTRACT AND CONTROL ROUTING

Shared entry points: evaluate(request)->overall decision+per-control results; emit(observation)->explicit durable/best-effort receipt; callback(later result)->correlated receipt; pull(scope,cursor)->source page+completion; query(control,scope,as_of)->recomputed assessment. query is for judges, separate from four enforcement transports. SDK/sidecar is an adapter form. These are our proposed names, not existing vendor APIs. Admission request: schema_version, authenticated team/point context, run_id, action_id, attempt_id, event_type, pinned_bundle_id, exact request identity, model/version/accounting options, trusted facts/bounds. Response: decision_id, overall ALLOW/DENY/ERROR, per-control control_id+spec_id+decision+reason, attempt_id, optional reservation_id and amount. Monitoring ALERT is not an admission refusal unless explicitly declared as a blocking policy. Mapping is frozen in the authorized policy bundle; caller cannot omit a required control or select an easier version. DENY or required-admission-control ERROR prevents dispatch. Recording/monitoring controls do not become blocking merely because they share an action. Proved-undispatched reservations can be cancelled after another gate denies; ambiguous ones remain reserved. Routing rows: model.requested at shared gateway ->16 admission;7 request/decision facts. model usage/outcome ->16 settlement and assessment facts;7 outcome recording. zoneA/zoneB handoff send/receive ->7 observations and pair reconciliation. permitted tool/handoff lifecycle ->7 according to declared scope. comparable metric window ->9 off-path evaluation and alert. ServiceNow delivery/result ->9 alert-operation evidence and optional declared7 recording. Unmatched in-scope actions become mapping gaps, not silent exclusions. A multi-run window has explicit run membership rather than a fictitious single run.

Exact schemas should be encoded during implementation from these required fields; no cloud table names are asserted. Reject missing/unsupported/expired bundles. Publishing a new bundle does not alter historical assessments or split an existing run's budget. Declare pin-to-completion vs stop-on-revocation; urgent revocation uses a separate distributed stop signal, not per-call registry reads. 4. CONTROL7: EXECUTABLE EXPECTED-EVENT CONTRACT

Initial in-scope taxonomy covers the three-zone subject run. Freeze the actual implemented source mapping; these are required logical obligations, not a claim that vendor payloads use these names. Run admission: lifecycle authority commits run.opened; closing actions requires run.actions_closed and source completion records. Model action: dispatcher/coordination journal registers model.requested; expects admission.allowed, admission.denied or admission.error. A recoverable admission error is its own declared terminal decision; an unrecorded outage remains a recording gap, never an invented denial. If allowed and actually dispatched, expects dispatch marker and one authoritative terminal outcome: completed, failed, or explicitly unresolved. Successful known usage requires a usage assertion; failed/disconnected outcomes may still incur tokens and require reconciliation. Denied never-dispatched work needs denial evidence, not fabricated provider usage. Each gatewayA/B handoff: sending lifecycle creates handoff.sent and expected matching handoff.received, joined by stable handoff_id; refusal/timeout is its own declared terminal case, never silently deletes expected work. Tool action: orchestrator registers tool.requested before dispatch; expects one tool.completed/tool.failed or unresolved outcome, with result/source reference. Include only explicitly declared tools across verified sources; excluded relevant sources remain a scope limitation. Each real retry adds a new attempt and its obligations, while the previous attempt remains reconcilable.

Dynamic example: three initial model attempts M1,M2,M3; M2's genuine retry M2R is separately registered before execution. All4 belong in expected accounting. Losing every telemetry record ofM2R still leaves an independent obligation/provider inventory entry. If the platform cannot supply an independent work inventory or verified complete interception, completeness cannot be asserted. The adapter's surviving logs alone are not an expected population.

Coverage: E=unique required obligations due by declared cutoff; O=valid matching recorded obligations; coverage=|E intersect O|/|E|. Extra, duplicate, orphan and conflicting events reported separately; cannot inflate numerator. Missing events do not disappear fromE after timeout. E=0 returns coverage NOT_ASSESSED with no division, not100%. Unknown source coverage means denominator is unproven: no full-scope SATISFIED. A proved violation may still establish BREACHED even when other evidence is missing. Timing: define consecutive events only within each declared ordered producer stream for one run, ordered by producer sequence and measured by a valid monotonic clock/epoch. Parallel branches are separate streams; no subtraction of unrelated host clocks. Restart/clock discontinuity creates an unmeasurable gap, not a new apparently clean stream. Exact policy declares gap< G, so violation isgap>=G. Build eligible expected adjacent pairs from independent stream/sequence slots or an authoritative pair inventory, not observed neighbors. Let their count beP, measurable pairsM, violating pairsK, unmeasurableU=P-M. A missing middle event leaves both expected adjacent pairs unmeasurable; never replace them with one observed-neighbor gap. A wholly missing stream retains its expected pairs. If expected order/pair membership is unknown, timing denominator is unproven and no numeric bounds or timing pass may be asserted. Report all4. With complete pairs, violation share=K/P; compare with allowedB7. With missing pairs, lower boundK/P and upper(K+U)/P bound the share; claim pass only under the predeclared completeness/measurement rules. P=0 returns timing NOT_ASSESSED, not automatic success.

Policy parameters not yet justified: coverage targetC, gap limitG, allowedB7, minimum evidence/timing coverage, eligible streams and late deadline. Complete the rule from permitted pre-assessment baseline/purpose, name owner, date it, then freeze. Illustrative fixture: E11,O11; ten gaps with one>=5ms; allowed10% ->satisfied if all other declared conditions hold. A second violating gap ->breached. These values mirror teaching examples, not final thresholds. Done gate: accepted scope spans all required zones; independently justifiedE; coverage+timing test; pass/breach cases under same spec; missing-whole-attempt and out-of-order cases; source-backed query and export.

6. CONTROL16: WHOLE-RUN ACCOUNTING AND OPTIONAL PREVENTION

Accounting test is the completion foundation. Whole-run actual usage sums authoritative input+output for every actual attempt across all3 agents and retries with declared cache/reasoning semantics. Reservation is exposure, not measured spend. Complete inventory and reconciled usage required for an under-cap pass. Known trustworthy subtotal>N proves run breach even with other missing usage. N remains a justified pre-assessment parameter;10,000 only an illustrative fixture.
