An enforcement point invokes a defined control interface. The control uses a frozen rule. The action and its outcome produce records that a separate test can assess.

The missing layer

We must specify the payload, applicable controls, decision behavior, state changes and evidence links before choosing infrastructure.

This page defines that layer. None of the adapters or cloud integrations is represented as implemented.

The slide is not asking for five API functions. It describes five architecture problems. The next slide explicitly says “one contract, four transports”: evaluate, emit, callback and pull. A sidecar/SDK is an integration mechanism. The query/test function serves judges separately.

Our proposed SDK / service contract · not existing vendor API names

One vocabulary, several ways to connect.

MethodWho calls whom?Meaning of the result
evaluate(request)Gateway or modifiable action adapter → our control entry point, before dispatch.Overall ALLOW / DENY / ERROR plus per-control decisions, pinned specs and reservation IDs. Required admission-control DENY/ERROR prevents dispatch; observational controls do not block by association. Required reservations commit before ALLOW.
emit(event)Source/adapter → asynchronous collection.Receipt states durable acceptance or best-effort receipt. Durable acceptance follows recoverable persistence; neither receipt means the control passed.
callback(result)Authenticated deferred workflow → our receiver, later.Correlated later outcome. Original action/spec retained; repeats and stale responses handled explicitly.
pull(scope, cursor)Our scheduler → source connector → permitted platform API/logs.Observations, cursor and completion information for a declared run/window. Polling alone does not prove completeness.
query(control, scope)Judge UI/CLI → our control test.Recomputed assessment plus measurement, rules, source references and gaps. This is separate from the four enforcement transports.

These are logical methods, not necessarily five public HTTP endpoints. An SDK can invoke code in-process; an approved service can use authenticated RPC. A gateway must actually be configured to call its adapter. Merely publishing an API does not integrate it.

The agent does not choose whether a control applies. The declared scope and trusted, pinned mapping select it. Preserve intentional exclusions and unmapped in-scope actions. A caller cannot bypass a required control by omitting its ID or supplying a different policy version.

A record can support more than one control

Identify the execution once. Link its observations and assessments.

RecordMeaningRelationship
Source E-42FM-A / action42 / attempt42-1 / actual 700 tokens / source referenceOne canonical observation.
Binding B-42-7E-42 supports AIA-LOG-001 under TEAM-C7-v1.Proves this expected outcome record is present; whole-scope coverage still needs reconciliation.
Binding B-42-16E-42 supports ACN-COST-001 under TEAM-C16-v1.Contributes 700 actual tokens once, despite being used by two controls.
Assessment T-16-FM-AComplete run test, frozen rule, expected attempts, observed usage, exceptions, gaps and verdict.References all supporting facts and the expected population.

Observation IDs and execution IDs are different: gateway and provider logs can report one attempt with different event IDs. Reconcile them under declared source authority; do not sum parent spans with leaf calls or silently discard conflicts. A business run spans all three agents; action IDs identify logical actions; attempt IDs distinguish real retries; event IDs handle delivery duplicates. Trace/span IDs are source pointers. Control9 windows carry explicit member runs and observations rather than forcing a multi-run interval into a fictional single run.

Admission and assessment answer different questions. ALLOW/DENY says whether to dispatch an action. SATISFIED/BREACHED/INDETERMINATE says whether the declared requirement held over the assessed scope. A denied overspend attempt is not an actual spend breach.

What the software and final submission must provide

A stranger asks a question. The tool answers with records.

“Show me control 16 for run FM-B.”
“Was control 9 satisfied for run FM-B?”

These are examples from the slides. Judges can choose a control and a run/window and expect a records-backed answer within two minutes.

Working software

Adapters, dated policy specifications and bindings, executable control logic, evidence collection/reconciliation, control tests and query/export tool, plus required governance integration.

Six required artifacts

Evidence export; threshold document; runnable test/query tool; named passing and breaching runs; one-page invocation architecture; gap list.

What to show in the answer

Applicable rule and date; expected vs observed population; calculation and limit; exceptions and gaps; source references; actual finding/owner state.

Prepare for rubric-derived follow-ups: Why this threshold? Which actions are missing? Did the safeguard work? Can someone else recompute it? How did the second adapter reuse the core? What broke under attack? Was the finding closed only after a passing retest?

The five architecture problems describe what the design must accommodate. They do not require building every possible control, every transport and every enforcement-point adapter to claim completion. Claim only the controls and integrations demonstrated end to end.

Three independent AI edge-case reviews

Review outcomes and fixes.

Three AI reviewers worked separately with the same model configuration and did not consult each other. They challenged the first draft against the supplied sources. The primary agent incorporated the changes below; this is a design review, not a tested implementation or reviewer certification of cloud behavior.

Reviewer / riskEdge caseDesign correction
Interface · criticalGateway crashes after sending inference but before recording its outcome.Durable RESERVED → DISPATCHING → OUTCOME_UNKNOWN / SETTLED states. Never blindly redispatch an ambiguous attempt; verified downstream idempotency is required for safe repetition.
Interface · highA changed request exceeds the reservation; a crash loses the decision record.Bind admission to the exact immutable model request and verified bounds. Commit a minimal transition journal/outbox with budget state; export rich evidence asynchronously.
Interface · highA new call races with run closure, or supplies another team’s run/policy.Validate authenticated scope, OPEN run and pinned authorized bundle in atomic admission. Separate action closure from evidence finality.
Evidence · highGateway and provider logs charge one execution twice, or all records of one branch disappear.Separate observation from accounting identity; reconcile authoritative per-attempt usage. Create independent expected obligations and expose missing source checkpoints, bypasses and conflicts.
Evidence · mediumMissing timestamps look like good timing; one window’s drift is presented as one run’s accuracy.C7 reports measurable and unmeasurable gaps separately. C9 fixes positive baseline, membership, direction and minimum samples; run queries expose applicable window scope.
Deployment · mediumA local green dashboard suggests complete submission or full-claim compliance.Show mandatory integration obligations and a C-FM-01 branch manifest. Unassessed controls prevent a full pass. Label adapters proposed / fixture-tested / live-verified / unavailable.
Deployment · mediumSuccessful denial is submitted as the required actual overspend case.Prepare an eligible, openly labelled breach case under unchanged thresholds. Confirm replay eligibility; keep the live prevention demonstration separate.

Still requires workshop verification: gateway type/hooks and bypasses; authoritative attempt inventory/usage; provider idempotency and token bounds; permitted compute/storage; ServiceNow trace/finding/callback permissions; Control9 baseline data.
