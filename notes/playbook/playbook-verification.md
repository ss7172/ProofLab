## Confirmed platform facts (playbook §2 consistent with our evidence)

- **Guardrail block:** a prompt-attack block = HTTP 200, `finish_reason=content_filter`, 0 tokens (gap 4).
- **C16 figure of record:** the gateway per-call line. Spans are a cross-check; AgentCore Latency/Errors are the drift signal (deck p19). The gateway's own spans in `aws/spans` carry the same per-call figures, by run id, for 30 days (corrected after live verification, 2026-10-05).
- **Ceilings:** 100 req/min and 2.5M tokens/h, account-wide.
- **Strands adapter:** `GatewayModel(OpenAIModel)` drops an empty `tools` list (`~/agents/my-agent/agent.py:40-44`).
- **Ledger reads:** `/records?cid=` is the machine read; `/timeline` is text. `audit-store.py` GET routes are `/healthz`, `/records`, `/timeline`.
- **Approval annotations** `modaas.tmforum.org/approver` + `approval-attestation`; `.status.governance.approvals` holds the records. `Approved` ≠ runtime READY.
- **Model swap (corrected after review and live verification, 2026-10-05):** the runtime model is the env var `MODEL_ALIAS`, set by the operator. It follows `spec.dependsOn.models[0]` whenever `modelRef` is absent or equals it (live on all 5 runtimes); which field wins when they differ is unverified (the CRD's field description says the operator injects `modelRef` as `MODEL_ALIAS`). A CRD rule (confirmed live, verbatim) requires `modelRef`, once set, to be one of `dependsOn.models`. The Module 7 swap set both fields on the IT agent (`nemotron-nano-9b`) in one patch, so a revert must update both consistently (or remove `modelRef`). Check the runtime's `MODEL_ALIAS`, not the guide's `.spec.modelRef` checkpoint.
- **TMF639:** `TMF639Projected=False` on approved CRs.
- **Direct Bedrock** is denied by IAM: an explicit Deny on the runtime role; the IDE role has no allow (read from the policies, not attempted).
- **AICT scope (corrected after review, 2026-10-05):** discovers AgentCore runtimes, and its role can list AgentCore gateways and targets; not EKS pods, the agentgateway's MCP routes, guardrails or per-ModelConfig attribution. The SN handoff's same sentence (§13.1) also claims Bedrock agents and SageMaker models, which the connector role is denied here.
