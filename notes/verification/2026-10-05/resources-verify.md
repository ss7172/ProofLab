## New facts worth recording

1. **Gateway spans in X-Ray carry `modaas.action_id`** (policy `modaas-telemetry-export` copies it from extauthz). The same `action_id` therefore links X-Ray, `/modaas/evidence` and the PDP log, and X-Ray is durable. **`modaas.run_id` is also present, but nothing shows it ever holds a run CID.** In the 5 traces we sampled (traffic with no CID), it was a 32-hex value shaped like a trace id. That fits authz falling back to the trace id, which adds nothing beyond the `trace_id` already in `/modaas/evidence`. It stays untested until someone samples a reference-agent run tagged with a CID, so #27 should not change yet.
2. **modaas-authz writes nothing per call to stdout.** Its per-call records go only to `/modaas/evidence` over OTel. Both the WHO step and the Trace-view fallback point at an empty log.
3. **PDP and authz pod logs aren't shipped to CloudWatch.** Decisions are durable only as `/modaas/evidence` records (30-day retention), and the gateway log keeps 7 days.
4. **`get-agent-runtime` works for the participant role and returns runtime env as plain strings.** The names include `AUDIT_WRITE_TOKEN`, `OPENAI_API_KEY` and `AGENTCORE_GATEWAY_MCP_TOKEN` (we printed no values). That is one more read path for the ledger token and the gateway bearer, on top of #24.
5. **Participants can use the apiserver pod proxy in `agentgateway-system`.** The `:15020` metrics GET succeeded. This extends #26, which lists secrets, pods and port-forward.
6. Events in `components` are kept for about 1 h and are all `reason=Logging`, so they are no use as WHAT evidence after the fact.
7. There are now 18 approval records, all with an empty `signature`. When #12 was written there were 14.
8. The cost catalog ConfigMap prices every Nemotron id in use, so the Cost view's dollars are not $0 or "no price" for our models. Tokens still come from AWS/Bedrock metrics (#42).
