## 1a. Checkpoint command lists AgentConfig, ModelConfig, ToolConfig and the other CRDs
- **Verdict:** CONTRADICTED. The command fails.
- **Evidence:** `kubectl api-resources --api-group=oda.tmforum.org --no-headers -o custom-columns='KIND:.kind'` returns `error: unable to match a printer suitable for the output format "custom-columns=KIND:.kind", allowed formats are: json,kyaml,name,wide,yaml`. `api-resources` doesn't accept custom-columns.

- **Notes:** not yet recorded. Candidate doc-drift item.

## 3. "Phase: Reviewing, Approved, Paused, Revoking"
- **Verdict:** PARTLY.
- **Evidence:** the `status.phase` enums in the served v1beta1 schemas (`kubectl explain`, CRD JSON):
  - **ModelConfig:** Pending, Reviewing, Validating, Validated, Configuring, Approved, Failed, Paused, Retired
  - **ToolConfig and AgentConfig:** Pending, Reviewing, Approved, Active, Failed, Paused, Retired
  - **Registry:** Ready, Degraded, Unreachable, Unknown, ReadOnly. These describe reachability, not approval.
- **"Revoking" is in no enum and doesn't appear anywhere in the four CRDs' text.** The API server would reject it as a phase value. The glossary also leaves out Pending, Failed, Retired, Active and the three ModelConfig-only phases (Validating, Validated, Configuring).
- **Live:**
  - 18 Approved: 4 ModelConfig, 9 ToolConfig, 5 AgentConfig.
  - 1 Reviewing: ToolConfig `demo-crm-lookup`.
  - None are Paused right now.

## 5. "Run id … Equals the traceparent trace id when every call in the run sends one"
- **Verdict:** PARTLY.
- **Evidence:**
  - **The page's own command** returns 3 lines from 2026-10-04T18:07Z, route `helper-docs-mcp-route`. Each shows `modaas.run_id="hackathon-helper-1791137236-102178"`, while `trace.id` and `modaas.trace_id` are both `6d367563…ae9bc2`. The run id is a **CID**, not the trace id, even though the calls carry a trace id.
  - **All 24h lines** with `modaas.run_id`: one pod, `modaas-agw-88dc46ff4-jfcdx`, up since 2026-10-04T10:35Z with 0 restarts.
    - 627 lines have a CID-shaped run id that differs from the trace id.
    - 384 lines have a 32-hex run id equal to `trace.id`.
- **Mechanism, read from the policies:**
  - `modaas-access-log` and `modaas-telemetry-export` both set `modaas.run_id <- extauthz.correlationId`.
  - `modaas-authz` forwards `baggage` and takes the correlationId from the authz response header `x-modaas-correlation-id`.
  - So when baggage is sent, the baggage CID wins. That the run id falls back to the trace id when no CID is sent is *inferred* from the 384 lines, not read from source.
- **Notes:** #21 (run_id is the baggage CID) and #27.
