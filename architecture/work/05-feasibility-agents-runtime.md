# 05 · Infrastructure feasibility: agents and runtime

Written 2026-10-05, 22:58–23:40 UTC, by the agents-and-runtime feasibility vetter (a subagent). It answers the captain's fear, "we are ok with the architecture but our infra does not support development", for the agents-and-runtime area of `architecture/ARCHITECTURE.md` (§3.1 EP-1/EP-3/EP-5/EP-11, §3.2, §3.4, §5.1, §5.3, §7, §8, §12, §14).

**Bottom line.** The platform supports building and running the `ifabric-` trio and the in-path C16 hook. There is one real conflict between the design and the infrastructure: the kit's build path ships **one source file**, so the planned layout of vendored modules does not build as written. The fix is packaging only (a single-file bundle with a size gate). Two run-plumbing defaults copied from the kit are must-fixes: the CLI retry that silently re-invokes an agent, and the time-only join on the AWS invocation log. Three questions still need a live write: the action-id header on streamed responses, the ledger POST from the laptop, and forced structured output on Nemotron.

**How this was checked.** Everything was read-only, as `WSParticipantRole` (profile `hackathon`, `us-east-1`):
- **Cluster:** `kubectl get/explain/auth can-i`.
- **AWS:** `describe`, `get` and `list` calls only, plus `logs get-log-events`.
- **Source reads:** the pinned wheels, downloaded into `scratchpad/vet-agents/` and never installed; the local snapshot of the platform source (`scratchpad/modaas-src/src/`); and the kit.
- **Not done:** no model call, no agent invocation, no build, no apply, no annotation. No secret value was printed. Env vars appear here as names only, and the account id is omitted.

1. **The AWS-written invocation records do carry the run.** `InvokeAgentRuntime` records in `/aws/bedrock/aict-invocations` hold `responseElements.runtimeSessionId`, `traceParent`, `baggage = modaas-correlation-id=<CID>` and `statusCode`. `eventTime` is the **end** of the call, and CloudWatch delivery comes about 5 min later.

## Top risks to the build

1. **The packaging trap (AR-03).**
   - The kit build copies one file. A vendored-module layout builds fine, approves fine and goes READY, then fails at the first invoke.
   - The buildspec cap (24,049 chars of gzip+base64 source) bounds the bundle.
   - Mitigation: the bundler, a CI size gate and a local arm64 Docker run before any CodeBuild run.
   - A related trap: calling `build-agent-image.sh` directly with a file named `agent.py` and no `IMAGE_TAG` pushes our image over the reference trio's tag `reference-agent-v5-agentcore`, overwriting the "untouched before system" artifact.
   - Mitigation: name the bundle `ifabric-<role>.py` and always pass a unique `IMAGE_TAG` (AR-05).
2. **Silent duplicate invocations (AR-18).**
   - The kit's invoke pattern re-sends a long invocation after 180 s, which already happened in S2.
   - Two copies of one agent then run from the same tally. That breaks the inline C16 guarantee and doubles C7's events.
   - Mitigation: `AWS_MAX_ATTEMPTS=1`, a long read timeout, and an in-flight `handoff.id` guard in the agent.
3. **Strands hook traps (AR-10 to AR-12).**
   - The deprecated `structured_output()` bypasses the hook.
   - `structured_output_model` turns a halt into an exception.
   - A self-cancel looks like a served 0-token call.
   - OpenAI's 2 hidden retries sit below the hook.
   - An `http_client` passed in `client_args` is closed after one call.
   - `content_filter` is mapped to `end_turn`.
   - All of these can be tested offline against a stub model in a 3.12 venv. Write those tests before the first build.
4. **A silent stale pin (AR-15).**
   - A rejected env patch sets the CR to Failed while the runtime keeps the old pin, and a run during UPDATING may hit the old version.
   - The model swap and the mode switch carry the same risk.
   - Mitigation: before each assessed run, check the runtime version and the pin the agent echoes back (EP-0).
5. **The time-only AWS-record join (AR-20).** As designed it mismatches every invocation. Switch to the exact CID and session-id join; it is free and stronger.
6. **The ledger server under our record volume (AR-21).**
   - It is single-threaded, every GET parses the whole file, its memory limit is 256Mi, and there is no fsync.
   - One whole-ledger export late in the event could OOM it. The PVC survives a restart, but the evidence window gets a gap.
7. **The shared account ceiling (AR-11).**
   - 429s set off up to 6 Strands retries with up to 240 s backoff, which stretches invocations past the script's timeout.
   - An observe-mode breach run spends the shared hourly budget.
   - Space runs apart, check headroom first (EP-9), and size the timeouts.
8. **Approval is a shared-role act (AR-07).** Anyone's shell can annotate as anyone. Separation of duties rests on process: Sree runs the command, and EP-10 records it.
