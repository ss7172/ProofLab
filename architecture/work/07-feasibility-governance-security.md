# 07 · Infrastructure feasibility: governance, policy and security

Written 2026-10-05 by the governance/policy/security feasibility vetter (a subagent). The captain's worry: "we are OK with the architecture, but our infra does not support development." This file checks that worry, one component at a time, for the governance, policy and security parts of `architecture/ARCHITECTURE.md` (§3.1 platform EP adapters, §3.3 control registry, §5.0 EP-0, §6 / D10, §11, §14) and `03-decision-options.md` (D5, D6, D10).

**How it was checked.** Read-only only:
- **Live reads** as WSParticipantRole (groups `modaas:participants`, `system:authenticated`), 2026-10-05 22:57–23:24 UTC: `kubectl get / explain / auth can-i / logs`, AWS `get / list / describe`, Logs Insights, CloudTrail `lookup-events`, IAM policy reads. Plus one TLS handshake with no credentials to the gateway's :8443.
- **Platform source:** `workshop-assets/modaas-aigateway-src.zip` (operators, PDP, authz-gateway, CRDs), extracted to the scratchpad. File and line numbers below refer to it.
- **Kit:** `workshop-static/starter/` and `workshop-static/lambda/`.
- **Memory:** `platform-verified-facts`.

**What was not done:**
- No writes, no `--dry-run=server`, no annotations, no pauses.
- No secret values were read into the output. Env was dropped with `--query` or jsonpath, and only a key count was read.
- `kubectl auth can-i` tests RBAC only. The admission verdicts for `components` come from the live VAP's CEL text, plus our own earlier writes there that it allowed (`my-agent`, the `modaas-docs` pause and resume).
- No account ids, hostnames or access keys appear in this file.

**Status key:**
- **SUPPORTED:** the platform does it today.
- **SUPPORTED-WITH-CAVEAT:** it works, with a stated limit or rule.
- **SPIKE:** an exact, minimal, reversible test, with its cost and approver.
- **BLOCKED:** cannot be done, or must not be done under our rules. A redesign is given.

## Top risks

1. **A Cedar rule that silently does nothing.** Three ways:
   - an adopt-mode ToolConfig: the platform's policy decides `tools/call` (GS-03);
   - a custom `policyId`: every call DENYs (GS-01);
   - a parse error: the PDP keeps the old policy (GS-09).

   *Mitigation:* the custom tool only; never set `policyId`; and before any adversarial run, check both surfaces (both PDP replicas log `version=<rv>`, and `/modaas/evidence` `policy_version` = rv).
2. **Evaluation errors fail closed.** A forbid that reads an absent attribute denies every call to our tool, including `initialize`. The tool becomes unusable, and the logged reason is "cedar errors", not our rule.

   *Mitigation:* guard every attribute with `has`, as the template does. SP-1 tests one allowed and one forbidden call.
3. **Leftovers that can't be undone, and name collisions.**
   - The projected ConfigMap and a DEPRECATED registry record stay after a delete.
   - A reused toolName would share, and on delete deprecate, a platform registry record.
   - In managed mode, deleting our CR could delete a platform gateway target.

   *Mitigation:* final `ifabric-` names from the first apply; never managed `agentCoreGateway` mode.
4. **The kill switch is easy to misread.**
   - An AgentConfig pause doesn't stop direct `InvokeAgentRuntime`.
   - A model pause hits every agent on that alias.

   *Mitigation:* the EP-0 preflight checks `spec.paused`; contain a run by pausing our own tool or by C16 `enforce`.
5. **Approval evidence is weak.** Approvals are self-asserted, have no signature and record no generation. The generation's source (PublishedNotification) is writable by participants, and edits never trigger a new approval.

   *Mitigation:* EP-0 uses three corroborating sources: the notification's generation, the Agent Registry's AWS-set `updatedAt`, and the runtime version history. The register gets the owner's ServiceNow record (T2).
6. **The guardrail is narrow and its version moves.** It blocks prompt attacks on input only, and its version changes on reconcile.

   *Mitigation:* capture the guardrail id and version per run; claim only what is configured. Hostile cases beyond prompt attack rely on agent judgment.
7. **The date proof has no Object Lock.** Only the IDE role can list versions, and noncurrent versions expire after 7 days.

   *Mitigation:* one PUT per version key, a `head-object` capture, and a person on the IDE runs `list-object-versions` for the pack.
8. **AICT and T2 depend on Arth's access to the shared ServiceNow instance** (SP-2). Start it early, in parallel.
9. **Traffic is plaintext.** The gateway key crosses in the clear on every MCP call, and the TLS certificate is a placeholder. Record it (gap 9); don't build around it.
